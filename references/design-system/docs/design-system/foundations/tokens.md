# Переменные, режимы и привязки

Основной источник для текущего проектирования выбран пользователем: DS-01 «air kit 3.0 → Дизайн система». Проверка источника — 29.09.2026. Владелец этого документа — главный агент. Здесь описаны наблюдаемые значения и связи; прямые авторские descriptions и рабочие рекомендации обозначены отдельно. Публикация библиотеки и допустимость overrides не установлены выбором файла.

Исходные данные нормализованы; генерация не присваивает готовность к применению. Актуальная независимая приёмка и её свидетельства находятся у [общего владельца статусов](<../acceptance.md>); состав и границы пакета записаны в foundation-status.json.

## Найти нужную запись

Начать с карточки применяемого компонента и его binding. Поиск через `scripts/find_design_context.py` должен быть ограничен DS-01 и точным именем переменной; после поиска прочитать найденную запись и её alias-зависимости. Для существующего слоя точнее искать по полному variable ID из Figma. Совпадающие имена и keys не заменяют файл, полный ID и конкретную привязку.

Нормализованные variables.json содержат весь ограниченный граф. Читать файл целиком для одной настройки не требуется. Поля `collection`, `valuesByMode`, `resolvedType`, `remote`, `description`, `scopes`, `hiddenFromPublishing` и `codeSyntax` сохраняют исходные сведения; `inLocalListing` и `sourceScope` различают происхождение записи. Дополнительное поле `type` повторяет resolved data type для совместимости поиска. `observedInFileKey` означает файл чтения, а не подтверждённый исходный файл внешней библиотеки.

## Локальные коллекции DS-01

Наблюдаемое устройство: **1285 локальных переменных**, из них 1243 COLOR и 42 FLOAT. Источник — `getLocalVariablesAsync`. Точные коллекции: collections.json.

| Exact name / полный collection ID | Количество в local listing | Режимы: exact name — mode ID | Default |
|---|---:|---|---|
| `theme` / `VariableCollectionId:114:62` | 173 | Light — `114:0`; Business — `3921:1`; Nova — `19680:2`; Portem — `19680:3` | Light |
| `color` / `VariableCollectionId:1004:1430` | 1070 | Main — `1004:1`; Alternative — `1004:6`; Image — `1004:7` | Main |
| `properties` / `VariableCollectionId:1004:1444` | 42 | L / 1440 — `1004:2`; M / 1024 — `7975:1`; S / 768 — `1228:0`; XS / 375 — `1228:1`; Mode — `21826:0` | L / 1440 |

Имена размерных режимов не задают автоматические responsive breakpoints. Имя `Mode` сохранено буквально; его авторская роль не установлена. Он отличается от `theme: Nova` и не должен выбираться по совпадению отдельных значений. Например, `content/radius/12` (`VariableID:4828:13921`) и `content/radius/10` (`VariableID:4828:13922`) в `properties: Mode` равны 0, в четырёх остальных режимах — 12 и 10.

Наблюдаемые scopes относятся к полям выбора переменной в Figma; это не перечень разрешённых автором overrides. Например, `component/buttons/negative/secondary/bg/active` (`VariableID:4487:7101`) имеет `scopes=[FRAME_FILL]` и `hiddenFromPublishing=true`. Доступность объекта по ID не подтверждает возможность импортировать его из опубликованной библиотеки.

| `colors/special cases - проблема здесь/Special-11 (Dark80 – Light10)`, `VariableID:5979:39778` | BG у туллтипа | Конкретное использование подтверждается binding компонента |

Упоминание скрытого/забронированного в другом description также не задаёт бизнес-условия бронирования.

## Alias и значения с opacity

У обычного `VARIABLE_ALIAS` значение указывает на полный ID другой переменной. Каждая цель разрешается в фактическом режиме **её собственной коллекции**. ID режима исходной коллекции нельзя переносить в другую коллекцию.

У шести `theme / colors/alpha/accent/{10%,20%,30%,40%,60%,80%}` в Light сохранена дополнительная форма:

```json
{
  "color": {"type": "VARIABLE_ALIAS", "id": "VariableID:8591:56074"},
  "opacity": 10
}
```

Это точное значение `colors/alpha/accent/10%` (`VariableID:8597:756`), а не прямой RGBA. Цель — `colors/accent/700`; native `resolveForConsumer` для проверенного Light consumer вернул RGB `#007BFC` и alpha `0.10000000149011612`. Все шесть native результатов и контекст consumer сохранены в проверке выражений. В этих шести выражениях зависимость ограничена theme; это не универсальная спецификация вычислений всех возможных expressions.

Рабочая рекомендация: сохранять форму значения и вложенный alias, а для используемого слоя сверять конечный результат через native resolver. Проверка только верхнего `value.type` пропустит такой alias. Ручная подстановка текущего RGB теряет зависимость от цели и темы.

## Граф зависимостей и remote representations

В evidence находятся **1319 distinct variable IDs**, полученных в разных областях:

| Происхождение | Добавлено | Что проверено |
|---|---:|---|
| Local variable listing | 1285 | Все значения перечисленных режимов |
| Замыкание локальных переменных и bindings local styles | 4 | Доступные по ID nonremote объекты вне local listing |
| Прямые bindings исходной анатомии master-компонентов | 22 | Дополнение к предыдущим 1289 объектам |
| Их транзитивные alias | 8 | Достижимые зависимости прямых bindings |

Master-область: 620 variable IDs и 28 style IDs в 84 семействах, 12523 исходных узла; обход останавливается на 3348 границах вложенных INSTANCE. В дополнительных 30 объектах — 13 nonremote и 17 remote. Причина отсутствия nonremote объекта в local listing не установлена; из этого нельзя делать вывод об удалённой или сломанной связи. 1319 не является размером всей внешней библиотеки.

collections-resolved.json сохраняет **10 полных collection IDs**: три локальных и семь remote representations. У последних keys совпадают с keys локальных коллекций, но IDs и наблюдаемые режимы отличаются. Например:

- `VariableCollectionId:76332c868eb4f2067421604c65e55a196f90c3ed/1281:618` — remote `properties` с desktop/tablet/mobile.
- `VariableCollectionId:ecde0750fe21c0b434ffa7c51090b1e815f6e53a/3921:2670` — remote `color` с Main/**Secondary**/Image.

Локальный `color` содержит **Alternative**. Объединять эти representations по имени или key нельзя: потеряется фактически применённый набор режимов. Порядок их появления, старшинство и политика обновления не установлены. В коллекциях поле `count` сохраняет число, сообщённое API, а `includedVariableCount` — число объектов этой коллекции в данном ограниченном evidence-графе; это разные показатели.

## Выбор и настройка в задаче

Это рабочая последовательность проекта, а не утверждение, что авторы DS разрешили любой override.

1. Выбрать карточку нужного DS-01 master-компонента, проверить её статус и конкретное состояние. Зафиксировать fileKey, node ID, component key и требуемую тему.
2. Прочитать binding изменяемого свойства точного слоя. Пустой `boundVariables` внешнего узла не исключает bindings внутри него. Если зависимость лежит внутри вложенного INSTANCE за границей evidence, прочитать её адресно в Figma.
3. Найти переменную по полному ID, затем её полную коллекцию. Определить фактический mode слоя, включая наследование и default. Зафиксировать его по каждой участвующей коллекции.
4. Проследить прямые и вложенные alias до конечного значения; для встреченного opacity-expression использовать подтверждённое native разрешение в нужном контексте.
5. Сохранить проверенную привязку при разрешённой настройке инстанса и проверить вид в нужном состоянии. Если предполагается смена source representation или override без подтверждённых правил, ограничить именно этот шаг до выбора целевого определения.

Неизвестные publication/import status, разрешённость overrides, роль `properties: Mode` и различия local/remote ограничивают соответствующие действия. Они не заменяют проверку контраста, поведения и layout конкретного компонента.

DS-04 и DS-05 остаются самостоятельными сравнительными снимками от 22.09.2026. Их IDs и evidence сохраняются; значения не переносятся в DS-01 по имени.

| Источник | Local listing / замыкание | Режимы `properties` | Evidence |
|---|---:|---|---|
| DS-04 «Токены Nova» | 541 / 837 | Четыре размерных + Nova (0) | Коллекции, bindings audit |
| DS-05 «Ревью токенов» | 540 / 618 | Четыре размерных | Коллекции, closure checks |

Nova-замыкание включает вложенные узлы исходных семейств; Review останавливается перед внутренностями вложенных INSTANCE. Между их local lists совпадают 540 имён, keys не совпадают; 65 определений/наборов modes отличаются (прежнее сравнение). Проверки локальных графов: Nova, 60 комбинаций, Review, 48.

У DS-01 с Nova/Review совпадают соответственно 450/449 точных пар collection name + variable name, но **ни один variable key**. Сравнения с Nova и с Review отделяют изменение имени, alias, mode и конечного значения. Совпадение всех 42 значений DS-01 `Mode` с Nova `Nova (0)` не устанавливает их одинаковое назначение.

## Обновление и проверка

Нормализованные JSON создаёт build_air_kit_foundations.py из проверенного research-пакета. Команда `python scripts/build_air_kit_foundations.py --check` проверяет полноту режима, уникальность IDs, прямые и вложенные alias, отсутствие циклов и точное соответствие generated output исходным данным. Проверенный локальный анализ покрывает 60 комбинаций режимов; расширенный граф проверен структурно, без декартова визуального прогона remote modes.

При изменении исходного variable ID/key, values, scopes, mode или binding сначала обновляется адресный read-only evidence и его независимая проверка. Затем генератор обновляет записи, главный агент — каталог и поиск, а потребители находятся через зависимости каталога. Изменение значения требует сверить затронутые состояния компонентов; переименование требует обновить маршруты, даже если цвет или размер совпали.

Обновлённый `audit_design_tokens.py docs/design-system/evidence/air-kit` проверяет вложенные alias, все полные collection IDs и каждое сочетание режимов коллекций, достижимых из данной переменной. Результат: 13 811 назначений режимов по корням, максимум 12 для одного корня; пропусков и циклов нет. Это проверка структуры графа, а не визуальный прогон и не повторение native вычисления opacity.
