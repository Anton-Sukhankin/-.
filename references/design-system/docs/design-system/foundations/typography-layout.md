# Типографика, сетки, эффекты и цветовые стили

Основной пользовательский источник — DS-01 «air kit 3.0 → Дизайн система», проверен 29.09.2026. Владелец документа — главный агент. Ниже различаются local styles, конкретно применённые remote definitions, прямые author descriptions и рекомендации выбора.

Исходные определения собраны и нормализованы; их наличие не доказывает публикацию библиотеки или разрешённость произвольного override. Актуальная независимая приёмка и её свидетельства — у [общего владельца](<../acceptance.md>), границы — в foundation-status.json.

## Найти и выбрать точное определение

1. У существующего компонента прочитать `textStyleId`, `fillStyleId`, `strokeStyleId`, `effectStyleId` или `gridStyleId` конкретного слоя, а также его bindings. Зафиксировать полный style ID, файл и состояние компонента.
2. Искать точное имя или ID через `scripts/find_design_context.py`, ограничив источник DS-01 и тип style. Маршрут поиска — styles-index.json; исходные записи находятся в styles.json. Для одной настройки читать только выбранную запись и обязательные зависимости.
3. Проверить `inLocalListing`, `remote`, имя, key и параметры. Если одному key соответствуют несколько полных IDs, сверить применённое представление с выбранным master-компонентом до смены привязки.
4. Для цветовых/effect bindings прочитать [токены и режимы](<tokens.md>). Название стиля не переключает variable mode автоматически.
5. После разрешённого применения проверить перенос, высоту текста и соседний layout в нужном состоянии. При неизвестном целевом представлении отложить его массовую замену; сохранить факт различия в задаче.

Это рабочие рекомендации проекта. Разрешённость настройки определяется источником и карточкой компонента; она не следует из того, что API позволяет назначить style ID. Источник старшинства local и remote versions пока не установлен.

## Локальная типографическая шкала

Все имена и числовые параметры ниже относятся к local listing DS-01. Это исходные значения стилей, а не правила автоматического масштабирования на узком экране.

| Семейство | Точные суффиксы размеров | Начертания | Высота строки |
|---|---|---|---|
| `Heading/` | 44, 40, 36, 28, 24, 20, 16, 14 | Без суффикса: CoFo Sans Medium; ` [a]`: CoFo Robert Medium Italic | ≈116% |
| `Label/` | 24, 20, 18, 16, 14, 12, 10 | Без суффикса: CoFo Sans Regular; ` [m]`: CoFo Sans Medium | 100% |
| `Paragraph/` | 24, 20, 18, 16, 14, 12, 10 | Без суффикса: CoFo Sans Regular; ` [m]`: CoFo Sans Medium | ≈140% |
| `Text/` | 24, 20, 18, 16, 14, 12, 10 | Без суффикса: CoFo Sans Regular; ` [m]`: CoFo Sans Medium | 150% |

Например, local `Paragraph/14` — `S:30f24c28ddbf4946663b08761a3f0512429675c1,`, lineHeight `139.9999976158142%`; local `Text/14` — `S:a229bf689cb8599177afcd15c0bee3b8e6846f05,`, lineHeight `150%`. Они сохраняются как два определения. LetterSpacing, paragraphSpacing, textCase и остальные поля нужно брать из exact record; таблица не объявляет их одинаковыми. Числа в JSON не округлены.

### Авторские descriptions

У 24 из 58 local TEXT есть непустое описание; 34 не имеют описанного назначения. Следующие роли подтверждены descriptions DS-01 на 29.09.2026:

- `Heading/44` — H1; `/40` — H2; `/36` — заголовок desktop-блока. Их ` [a]` — акцентные версии.
- `Heading/24` — заголовок внутри desktop-блока либо главного экрана/блока mobile; `/20` — внутри desktop-карточки либо mobile-блока; `/16` — внутри mobile-карточки. У этих размеров описаны акцентные ` [a]`.
- `Label/18 [m]` — desktop-подзаголовки; `/16 [m]` — заголовки карточек сервисов/списков desktop и mobile, также mobile-подзаголовки; `/14 [m]` — табы, кнопки и свитчеры desktop/mobile. `Label/12` — подзаголовки элементов.
- `Paragraph/18` и `Text/18` оба описаны как основной desktop-текст; `/16` обоих семейств — основной mobile-текст; `/14` — описание desktop-карточки; `/12` — информационные сноски desktop/mobile и описание mobile-карточки.

Совпадение назначения Paragraph и Text не разрешает выбрать между 140% и 150% по описанию. Для существующего компонента основание — точный применённый ID и проверенный master. Для нового элемента, когда эти определения дают разные результаты, требуется выбор целевого определения в задаче. У `Heading/28`, `Heading/14` и остальных records без description роль не установлена. Суффикс `[m]` не переносит назначение regular-стиля на medium автоматически.

## Local и remote при одинаковом key

Дополнительные определения подтверждают различия внутри DS-01. Не установлено, какое из представлений старше и какое авторы считают целевым для массового обновления.

| Общий key | Local definition | Применённый remote definition |
|---|---|---|
| `75844f6d8a41e0125a192b22cd358c76f0994a7f` | `Paragraph/14 [m]`, ID заканчивается запятой; lineHeight≈140%, tracking −1% | `S:75844f6d8a41e0125a192b22cd358c76f0994a7f,177:119`: `Text/14 [m]`, lineHeight≈120%, tracking −1,5% |
| `a5cfc589e639230ba53296f26a49751dd46c65fe` | `Paragraph/12 [m]`, ID заканчивается запятой; lineHeight≈140%, tracking −1% | `S:a5cfc589e639230ba53296f26a49751dd46c65fe,177:120`: `Text/12 [m]`, lineHeight≈120%, tracking −1,5% |
| `0824e81fca3b0322691e2f7838405aa44a1233de` | `Heading/36`, `S:0824e81fca3b0322691e2f7838405aa44a1233de,`, fontSize 36 | `S:0824e81fca3b0322691e2f7838405aa44a1233de,932:4`: `Heading/40`, fontSize 40 |

Ещё у remote `Label/12 [m]` (`S:4fc6aba4488b69ef2e497b3ea45ca8eb0bac5e63,2992:2`) tracking −0,5%, у local — −1%; у remote `Label/14 [m]` (`S:d01ed97ef09cae0675a76cd5d194c48bc544244a,932:13`) — −1,5%, у local — −1%. У `Shadow/Menu` различаются точные alias IDs при совпавших числовых effects.

Таким образом, надпись о Text/120% в пояснениях не заменяет чтение фактически применённого definition: одновременно обнаружены local Text/150%, local Paragraph/140% и приведённые remote Text/120%. Автоматическая нормализация по имени либо key изменит реальные параметры части слоёв. Для переноса такого компонента нужно сначала установить требуемый source definition; независимое описание конфликта не означает готовность к массовому rebinding.

## Сетки

Источник — четыре GRID records в styles.json. Таблица описывает первый слой многослойного стиля.

| Exact name | Первый слой | Gutter | Offset | Всего слоёв |
|---|---|---:|---:|---:|
| `grid — desktop, 1440` | COLUMNS, STRETCH, 12 | 8 | 60 | 6 |
| `grid — tablet, 1024` | COLUMNS, STRETCH, 6 | 8 | 32 | 2 |
| `grid — tablet, 768` | COLUMNS, STRETCH, 6 | 8 | 32 | 2 |
| `grid — mobile, 375` | COLUMNS, STRETCH, 6 | 4 | 20 | 3 |

Остальные layers имеют собственные count, alignment, offset и иногда sectionSize. Например, desktop содержит MAX/CENTER-направляющие, mobile — дополнительную направляющую с offset 8. Полный стиль применяется целиком; один первый слой не описывает все направляющие. Назначение дополнительных слоёв авторским description не установлено.

Размер в имени — наблюдаемая ширина макета. Пороги переключения, диапазоны ширин, перенос колонок и scaling не заданы этими стилями. Два имени tablet не определяют момент выбора каждого. Обнаруженные на странице таблицы отступов с разным происхождением также нельзя объявлять одним правилом только по заголовку или наличию рядом со стилями.

## Сравнительные снимки Nova и Review

DS-04 Nova и DS-05 Review остаются отдельными источниками от 22.09.2026: по 148 local styles (44 TEXT, 6 EFFECT, 4 GRID, 94 PAINT). Прежние точные IDs и определения сохранены: Nova typography, продолжение 15, продолжение 30, Nova GRID, Nova EFFECT, Review styles. Их прежняя независимая проверка относится к прежнему объёму.

У DS-01 совпадают exact names 44 TEXT, 6 EFFECT и 4 GRID, но ни один style key/ID с этими двумя источниками не совпадает. Четырнадцать Paragraph — дополнительные local names. У десяти одноимённых TEXT изменён tracking относительно обоих снимков:

| Exact name | Nova / Review | DS-01 local |
|---|---:|---:|
| `Label/12` | −1,5% | −1% |
| `Label/12 [m]` | −0,5% | −1% |
| `Label/14`, `Label/14 [m]` | −1,5% | −1% |
| `Text/10`, `Text/10 [m]` | −1,5% | −0,5% |
| `Text/12`, `Text/12 [m]`, `Text/14`, `Text/14 [m]` | −1,5% | −1% |

Сравнимые сохранённые параметры шести EFFECT и четырёх GRID совпадают. У Review в прежнем экспорте отсутствует root `boundVariables`; это отсутствие поля, а не доказательство отсутствия bindings. Часть типографических полей DS-01 также не сохранялась в прежних выгрузках, поэтому полное равенство всех свойств не утверждается.

94 PAINT каждого прежнего источника имеют группы `Light` (41), `Buisness` (33), `Gradients` (8), `Opacity` (12). Их нельзя предъявлять как local styles DS-01. Полные сравнения и границы полей: Nova, Review.

## Поддержка и проверка применения

build_air_kit_foundations.py воспроизводит 81 exact style record с сохранением ID, key, definitions, descriptions, bindings и происхождения. `python scripts/build_air_kit_foundations.py --check` сверяет generated evidence; общий индекс интегрируется главным агентом. Успешная структурная проверка не заменяет визуальную сверку текста и компонентов.

Изменение name, ID, key, параметра или binding требует повторного адресного чтения источника, сверки фактических потребителей по зависимостям каталога и обновления индекса. При изменении text metrics проверить перенос и размеры затронутого состояния. Неизвестные production/publication status, допустимые overrides, целевое состояние расходящихся representations и полная адаптивная спецификация остаются ограничениями соответствующего применения.
