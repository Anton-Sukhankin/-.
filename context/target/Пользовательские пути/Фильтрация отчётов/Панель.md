# FL-01 · общая панель фильтрации

Один владелец черновика общей панели, Apply/Reset/закрытия и сочетания условий. Меню колонки имеет собственную транзакцию FL-02.

Связанный родитель: [Фильтрация отчётов · общий целевой путь](<../Фильтрация отчётов.md>). Правила соседних блоков подключаются по ссылкам; данные и состояние родителя не копируются.

## FL-01 Выбор, применение и сброс

**Вход:** открыт текущий список отчётов, известен его контекст и вид. Позднее прямое решение разрешает общую кнопку справа и в таблице, сохраняя быстрые фильтры заголовков. Прежнее ограничение «только в карточках» заменено именно для отчётных списков главной и каталога. Это не правило для всех сущностей.

| Начальное состояние / действие | Целевой UI-результат | Граница подтверждения |
|---|---|---|
| Список → кнопка с иконкой фильтра | Открыта правая панель поверх текущего представления | Кнопка и панели собраны; Present заново не проигрывался |
| Панель → выбор атрибута | Открывается его dropdown | Отдельные компоненты/реакции настроены; открытые состояния показаны |
| Dropdown → выбор значения | Выбор виден до общего применения | Выбранное и применённое — разные состояния, не обещание транзакционного backend |
| Есть выбранное условие → общий «Применить» | Видна соответствующая выдача и индикация активных условий | В Figma подготовлен доменный пример; принятые правила сочетания ниже не подтверждают обработку полного продуктового набора или работу сервера |
| Применён домен → смена карточек/таблицы | Сохраняются домен и текущий контекст набора | Показан и связан доменный пример, не все сочетания |
| Активный фильтр → сброс | Очищается относящийся к действию выбор; сохраняется текущий вид списка | Локальный сброс колонки и общий сброс панели различать; [транзакция общего сброса](<Панель.md#общий-сброс-и-счётчик-черновика--решение-3-ноября-2026>) задана пользователем. Историческая настройка reset в Figma не подтверждает её исполнение |
| Общая правая панель → «Закрыть», внешний клик или Escape | Закрыть панель, отменить только неприменённые изменения; сохранить применённые фильтры и соответствующую выдачу | [Прямое решение 3 ноября 2026](<Панель.md#закрытие-общей-панели--решение-3-ноября-2026>); локальное меню колонки регулируется FL-02 |

В таблице быстрый фильтр заголовка и общая панель относятся к одним выбранным условиям. При применённом атрибуте заголовок показывает индикатор; поздний выбранный символ — минус в круге, с серым hover для сброса. Общая кнопка списка показывает количество применённых активных атрибутов, а не число выбранных значений; headline-счётчик открытой панели использует [отдельный черновик](<Панель.md#общий-сброс-и-счётчик-черновика--решение-3-ноября-2026>). Не создавать второй независимый набор фильтров для другого вида.

### Закрытие общей панели · решение 3 ноября 2026

Область — общая правая панель отчётных фильтров над избранным или каталогом, в карточном и табличном представлении.

| Исходное состояние / действие | Обязательный результат |
|---|---|
| Открытая панель с неприменёнными изменениями → «Закрыть», внешний клик или Escape | Панель закрывается; неприменённые изменения отменяются. Уже применённые фильтры, их applied-индикация в списке и соответствующая выдача сохраняются |
| Повторное открытие после такого закрытия | Панель показывает применённые условия; отменённый черновик не восстанавливается |

Пример приёмки: домен «Гостеприимство» уже применён; в панели выбран другой домен, но общий Apply не нажат. По отдельности проверить «Закрыть», внешний клик и Escape: после каждого закрытия остаётся выдача применённого домена; при повторном открытии показан тот же применённый домен.

Основание — прямой ответ пользователя 3 ноября 2026: «Да, отменять неприменённое». Общий «Сбросить» и headline-счётчик определены отдельным [решением о черновике панели](<Панель.md#общий-сброс-и-счётчик-черновика--решение-3-ноября-2026>). Закрытие панели не меняет отдельную транзакцию локального меню FL-02.

### Общий сброс и счётчик черновика · решение 3 ноября 2026

Область — открытая общая правая панель фильтров отчётов. Её DRAFT отделён от APPLIED текущего списка; локальное меню колонки продолжает использовать FL-02.

| Исходное состояние / действие | Обязательный результат |
|---|---|
| Открытая панель → общий «Сбросить» | Снять все условия DRAFT; оставить панель открытой. APPLIED, соответствующая выдача и индикаторы таблицы не меняются |
| После общего сброса → общий «Применить» | Применить очищенный DRAFT к текущему списку; обновить выдачу и APPLIED-индикаторы |
| Пользователь меняет выбранные условия в панели | Headline-счётчик показывает количество заполненных атрибутов DRAFT. Несколько значений одного атрибута дают один атрибут в счётчике |
| DRAFT отличается от APPLIED | Headline-счётчик отражает DRAFT; индикаторы таблицы и общей кнопки списка отражают APPLIED до применения |

Значение, означающее отсутствие ограничения, не считается заполненным атрибутом. В частности, [«Все» у статуса проверки](<../../../../specs/Общие компоненты/Фильтрация отчётов/Контракт.md#статус-проверки--решение-3-ноября-2026>) не добавляет условие в счётчик. После общего сброса headline-count равен0; уже применённый фильтр остаётся в списке до Apply.

Пример приёмки: открыть панель с применённым доменом → общий «Сбросить» → панель остаётся открытой, headline-count0, доменная выдача и её applied-индикация прежние. Закрыть без Apply и открыть снова: восстановлены применённые условия. Повторить сброс и нажать Apply: ограничение снимается с выдачи. Отдельно выбрать несколько значений одного атрибута и ещё один атрибут: headline-count2, не число значений.

Основание — прямое согласие пользователя 3 ноября 2026 с предложенными общим Reset и разделением DRAFT/APPLIED-счётчиков. Это UI-правило прототипа на согласованных demo-данных, не контракт API, серверного вычисления или хранения.

### Сочетание условий и поиск значений · решение 3 ноября 2026

Исключение, явно уточнённое пользователем4ноября2026: «Статус проверки» в общей панели допускает одно значение. Выбор нового статуса заменяет прежний, повторное нажатие текущего сохраняет его; «Все» снимает ограничение. Выбор остаётся DRAFT до общего Apply. Внешний вид без чекбоксов и цвет hover определены у [владельца компонента](<../../../../specs/Общие компоненты/Фильтрация отчётов/Контракт.md#статус-проверки--решение-3-ноября-2026>). Правило нескольких значений ниже относится к атрибутам с множественным выбором.

Область — выбор дискретных значений атрибутов отчёта в локальном меню колонки и общей панели. Оба способа используют одни применённые условия для текущего контекста набора; момент применения задаётся FL-01 или FL-02.

| Условие | Обязательный результат |
|---|---|
| Выбрано несколько значений одного атрибута / колонки | Значения объединяются по ИЛИ: отчёт удовлетворяет этому атрибуту при соответствии хотя бы одному из выбранных значений |
| Активны условия разных атрибутов / колонок | Условия объединяются по И: в выдачу входят отчёты, удовлетворяющие каждому активному атрибуту |
| В поле поиска списка значений введён запрос | Список значений ограничивается вариантами, в отображаемой подписи которых запрос встречается как подстрока, без учёта регистра. Это поиск значений данного атрибута, а не глобальный поиск отчётов и не самостоятельное применение фильтра |

Примеры приёмки: два выбранных домена допускают любой из этих доменов; дополнительное выбранное значение платформы ограничивает результат этой платформой. В списке доменов запрос «ГОС» находит «Гостеприимство». Изменение списка вариантов поиском не заменяет действие Apply.

Основание — прямое подтверждение пользователя 3 ноября 2026: «Да, подходят» для предложенных ИЛИ внутри колонки, И между колонками и поиска по подстроке без учёта регистра. В frontend-прототипе проверка выполняется на явно заданных согласованных demo-данных. Это не определяет API, формат серверного запроса, источник справочников, серверный total, права или хранение и не доказывает работу фильтрации в действующем сервисе. Это решение не задаёт диапазоны: их последующая семантика определена в решении4ноября ниже; несовместимые предметные условия остаются открытыми. Сортировка локальных demo-значений имеет [отдельное принятое правило](<Колонка.md#сортировка-локальных-demo-данных--решение-3-ноября-2026>); оно не определяет серверный компаратор.

### Числовые диапазоны · решение 4 ноября 2026

Пользователь поручил заменить множественные значения MAU и последнего просмотра диапазонами во всех отчётных фильтрах, разместить их на полную ширину общей панели друг под другом и добавить под MAU одиночные чипсы. Пороги10/50/100/500 подтверждены отдельно. [Компонент, геометрия и источники DS](<../../../../specs/Общие компоненты/Фильтрация отчётов/Контракт.md#настройки-числовых-атрибутов>).

| Действие / состояние | Обязательный результат |
|---|---|
| Введены нижняя/верхняя границы | Обе включены; пустой край не ограничивает значение с этой стороны |
| Оба края пусты | Нет ограничения, атрибут не увеличивает счётчик |
| Выбран чипс MAU | Нижний порог10/50/100/500, верхний отсутствует; выбранный чипс один; повторное нажатие сохраняет его |
| Введён ручной диапазон | Чипс активен только при точном соответствии нижнему порогу без верхней границы; иначе ни один |
| Последний просмотр | Давность в неотрицательных целых днях,0сегодня; меньшая давность означает более недавний просмотр |
| Значение строки отсутствует («—») | Без диапазона строка остаётся; при активном диапазоне не считается0 и не удовлетворяет условию |
| Одновременно заданы MAU/просмотр и другие атрибуты | Все активные атрибуты объединяются по И; дискретные множественные значения других полей сохраняют ИЛИ |
| Диапазон задан с двух сторон | Считается одним заполненным атрибутом; два числовых атрибута дают2 в счётчике |
| Отрицательное, дробное, небезопасное целое или «От больше До» | Ошибка черновика; Apply недоступен и обработчик также не применяет его; исходная выдача сохраняется |
| Изменение внутри общей панели | Меняется DRAFT; только общий Apply меняет выдачу и applied-индикацию |
| Изменение внутри меню колонки | Локальный DRAFT; Apply применяет диапазон и выбранную сортировку, затем закрывает меню. Reset сразу снимает APPLIED-диапазон этой колонки, закрывает меню и сохраняет остальные условия и применённую сортировку |
| Закрытие без применения | Предыдущее правило отмены DRAFT сохраняется; повторное открытие восстанавливает APPLIED |
| Смена вида списка | Те же диапазоны и набор объектов; фильтрация предшествует пагинации |

Диапазоны общей панели и колонок используют одно APPLIED-состояние текущего раздела. Избранное и каталог сохраняют независимые наборы условий. Пороговые значения — согласованная настройка демопрототипа; формула месячного MAU, источник времени, часовой пояс/календарь сервера, API и хранение этим не утверждаются.

### Клавиатура и фокус общей панели · зафиксированный срез

Эта таблица описывает наблюдаемую механику **панели отчётов в каталоге и избранном** среза prototype-2026-11-04-c1. Источник — [useReportFilterPanel](<../../../../references/implementation/app/useReportFilterPanel.ts>). Семантика отмены и применения остаётся в FL-01 выше; внутренние native checkbox/radio и самостоятельный single-choice-popup не получают от этой таблицы новую общую механику. | Условие / действие | Наблюдаемый результат |
|---|---|
| Открыта панель | Фокус получает её первая кнопка — закрытие в шапке |
| Открыт обычный список значений | Фокус получает первый input списка, если он есть: поиск при его наличии, иначе первый native контрол выбора; для отсутствующего input новый fallback не объявляется |
| Tab с последнего доступного элемента панели/списка; Shift+Tab с первого | Фокус переходит соответственно на первый или последний доступный элемент этого общего контура. Отключённые и неотображаемые элементы в него не входят |

| Открыт preview переполненных выбранных тегов и нажат Escape | Сначала закрывается preview и фокус возвращается к его счётчику по B04; общий обработчик панели этот Escape не обрабатывает |
| Закрытие кнопкой/фоном панели либо успешное Apply | После закрытия фокус возвращается к открывшей панель кнопке. Apply/отмена сохраняют свои разные результаты FL-01 |

Это подтверждённая часть текущего жизненного цикла, а не обещание полного keyboard-контракта всех overlay системы. Неподтверждённые состояния и внешние producer не достраиваются по аналогии.


## Панель и состав

Пользователь задаёт правое расположение и отступы24 px от верхнего, правого и нижнего краёв viewport. Позднее явно принята ширина480 px; ранние640/600 px исторические. Фильтры используют состав соответствующей таблицы: Отчёт, MAU, Платформа, Домен, Мастер-система, Владелец, Просмотр; позднее «Все» перенесено в панель как Статус проверки. Конкретные значения берутся из соответствующего набора, не из чужого раздела и не из synthetic MagicPath.

Панель адаптирована из DS-компонентов; наличие цельного готового DS drawer не заявляется. Общий footer содержит primary «Применить», «Закрыть» и «Сбросить» слева в выбранном состоянии. Внутренние dropdown используют поздние принятые локальные мастеры; старые изображения с другими названиями/расположением кнопок не являются текущей спецификацией. Сочетание значений и поиск вариантов определены в [решении 3 ноября](<Панель.md#сочетание-условий-и-поиск-значений--решение-3-ноября-2026>). Семантика диапазонов уточнена4ноября в разделе «Числовые диапазоны» этого пути; несовместимые предметные условия остаются открытыми.
