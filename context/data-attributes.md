# Реестр состава карточек

Экспорт связанного владельца для передачи frontend-разработчику. Архивные свидетельства не включены; условия, статусы и неизвестные сохранены. Для конкретного вида и состояния сначала читать принятый контракт в `specs/`.



**Владелец атрибутивного состава по разделам, типам и глубинам — этот реестр.** Исходный срез — 19.10.2026; 20.10 уточнены маршруты примеров и видимая подпись ранжирования по тем же исходникам. Это не новый срез действующего сервиса. Он объединяет подтверждённый текущий состав и применимость требований источника, сохраняя их разные статусы. Это не утверждённая полная спецификация всех карточек, не схема API и не разрешение дополнять Figma неизвестными полями.



В карте интерфейса остаются компоновка экранов, контролы и наблюдаемые состояния; система и данные владеет смыслом понятий и ролей; [Навигатор](<navigator-foundation.md>) — взаимодействиями и локальными последствиями требований. Извлечённые R-M/R-P/R-C остаются у [владельца требований](<requirements.md>). Этот реестр ведёт их полевую применимость, а не вводит второй набор требований.



## Как читать поле



| Метка / глубина | Значение |

|---|---|

| Н · наблюдается | Поле или визуальный элемент виден на названном кадре. Это не обязательность для всех объектов, ролей и версий |

| Б · требование брифа | Источник требует отображения в указанной глубине и применимости. Это не доказательство внедрения и не ограничение NOT NULL в данных |

| Р · рабочая композиция | Выбранный состав демонстрационного макета. Его нельзя принимать за показанный сервис или универсальный контракт |

| ? · не установлено | Нет достаточного источника; вопрос остаётся на согласование |

| С · список/выдача | Существующая строка или карточка раздела. Наблюдаемые варианты С не приравниваются к целевой mini |

| М · целевая mini | Мини-версия поиска из SRC-04:62–71. Не переносится автоматически на новости, подписки, вклад или избранное главной |

| П · предпросмотр | Дополнительная детализация рядом с выдачей. Наблюдаемая правая панель AI — локальный пример; целевой П наследует весь М по SRC-04:73 |

| Ф · полная карточка | Отдельный предметный обзор. Универсальное правило «Ф наследует всё из М/П» источником не сформулировано |



**Общие значения по умолчанию для всех строк Н:** обязательность заполнения и видимость по ролям неизвестны; условие показа ограничено названным вариантом/учётной записью. Если пустота не описана в строке, её отображение **не установлено**. Отсутствие строки, усечение текста, явное «Не указано», прочерк и число 0 — разные случаи. Пример заполненного поля не разрешает скрыть неизвестное обязательное поле в target и не делает его обязательным в текущей реализации.



Для строк Б обязательность **отображения** дана источником. Только поля, прямо названные обязательными в SRC-04:64, имеют дополнительную отметку «явно обязательное поле». Условия отсутствия данных, обязательность заполнения, источник прав, авторство/период показателей и поведение ошибок остаются неизвестными, если конкретная строка не устанавливает исключение. Нули и даты не генерируются вместо отсутствующих данных.



## Границы JSON примеров



[Значения примеров карточек.json](<example-values.json>) — выборка буквальных значений с адресными источниками, а не полный seed всех экранов. Она содержит выбранные строки отчётов, метрику, источник списка, два прежних полных паспорта, рассылку и подписку на главной. SRC-09 добавляет отдельные выборочные примеры полного отчёта ID 193 и полного показателя ID 4; старые значения сохранены. Отдельных полных наборов избранного, новостей, участников вклада, AI Hub и административных списков в ней нет. Отсутствие примера в JSON не отменяет поле, подтверждённое в этом реестре; значение для нового примера читается с его собственного исходника, а не переносится из похожего объекта.



Для «Моих подписок» исходная инструкция подтверждает имя подписки отдельно от имени отчёта, состояние, следующую отправку, канал/подсказку и отписку. В источниках этого блока показан только переключатель «Отчёты». Три вкладки «Отчёты / Источники / AI Hub» из SRC-01 принадлежат избранному; SRC-09 дополнительно показывает там «Метрики». Статус «Включена» — данные подписки; способ рисования тега и кнопок относится к [целевой композиции](<requirements.md#рабочая-композиция-подписок--уточнение-пользователя-20-октября>), не к расширению набора исходных атрибутов.

В целевой общей выдаче по брифу применяются шесть строк типов **отдельно**: отчёт — М-общее+отчёт / П-общее+отчёт / Ф-отчёт; источник — М-общее+источник / П-общее+источник / Ф-источник; метрика — М-общее+единица / П-общее / Ф-метрика; термин — М-общее / П-общее / Ф-общее; процесс — М-общее+группа / П-общее / Ф-процесс; ИИ-решение — М-общее+тип решения / П-общее+материалы / Ф-общее. Это применимость брифа, а не наблюдение шести работающих карточек или полнота текущего рабочего прототипа. Для П в каждой такой строке сохраняется весь соответствующий М.



## Наблюдаемый состав списка и правой панели



Это канонический перечень **видимых полей и визуальных атрибутов по вариантам**, дополняющий описание компоновки UI ниже. Основание — исходные кадры записи и вложения инструкций, а не новый wireframe, генерация изображения или перечень полей брифа. Область подтверждения — показанная учётная запись; видимость по всем ролям, API, обязательность и полнота заполнения не установлены.



Манифест 14 заготовок A и его чтение помогают сопоставить 127 полевых вхождений с исходниками. Это не 127 разных полей и не доказательство полноты всего сервиса. Схематические перерисовки, значения-заполнители вроде `[Владелец]` и внутренние ключи заготовок не являются буквальными значениями или именами API исходной системы. Сверка ниже опирается на сами изображения; наблюдения по форме и неподтверждённая семантика различаются.



Фильтры, поиск, сортировка, диапазон выдачи и счётчики найденного ведутся отдельно в перечне контролов. Счётчик у конкретного объекта — другой атрибут, не число найденных результатов. Действия и состояния объектов также отделены от полей данных.

Для остальных строк таблицы требуется отображение признака по брифу; его отсутствие в текущем образце не отменяет требования. Конкретные условные и пустые состояния не определены: неизвестно, что делать без владельца/фото/описания/единицы/MAU или источника личного признака. Не подставлять 0, случайное фото, автоописание, «не просмотрено» или «не владелец» без достоверных данных и согласованного правила.

## Фильтры, маркеры и действия



В реестре полями объекта считаются предметные данные; личные признаки и визуальные маркеры перечисляются отдельно по роли, а кнопки/вкладки/выбранность — по UI. Найдено/диапазон/число вкладки — счётчики выдачи, не показатели объекта. Глаз, указатель и сердце не получают неподтверждённых бизнес-формул; статус проверки карточки, статус объекта, ПДн, чувствительность и несистемные источники остаются разными признаками.



Подробный наблюдаемый состав фильтрации ведётся только в перечне контролов. **Каждое поле утверждённого базового фильтра должно быть видно в применимом М** (SRC-04:63). Обратное правило «каждое поле карточки — фильтр» не следует. Сейчас не утверждены полный реестр базовых фильтров и целевая типовая применимость.



| Доступное свидетельство | Что сверяется с М | Что остаётся неизвестным |

|---|---|---|
