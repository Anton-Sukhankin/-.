# Примеры карточек и границы сверки

Владелец границ приложения с буквальными примерами и исторической сверки. Полевые обязанности читаются у [корневого владельца](<../Состав карточек.md>), наблюдаемые каталоги — в [каталогах и паспортах](<Наблюдаемые каталоги и паспорта.md>), главная и дополнительные поверхности — в [отдельном чтении](<Главная и дополнительные поверхности.md>).

14 вариантов и 127 полевых вхождений относятся к исходной выборке; временные мастера и рабочая композиция **Р** не являются новым источником **Н** или требований **Б**. Примеры поздних срезов не заменяют старые: [SRC-09/SRC-10](<../Состав карточек.md#дополнение-по-src-09src-10--запись-21-октября-2026>), [SRC-11/SRC-12](<../Состав карточек.md#дополнение-src-11src-12--данные-поверхностей-30-октября-2026>). В [JSON значений](<../Значения примеров карточек.json>) дополнения сохраняются отдельно, включая `source11Examples`; отсутствие выбранного примера не отменяет подтверждённое поле.



Связанный родитель: [Реестр состава карточек](<../Состав карточек.md>). Правила соседних блоков подключаются по ссылкам; данные и состояние родителя не копируются.

## Границы JSON примеров



[Значения примеров карточек.json](<../Значения примеров карточек.json>) — выборка буквальных значений с адресными источниками, а не полный seed всех экранов. Она содержит выбранные строки отчётов, метрику, источник списка, два прежних полных паспорта, рассылку и подписку на главной. SRC-09 добавляет отдельные выборочные примеры полного отчёта ID 193 и полного показателя ID 4; старые значения сохранены. Отдельных полных наборов избранного, новостей, участников вклада, AI Hub и административных списков в ней нет. Отсутствие примера в JSON не отменяет поле, подтверждённое в этом реестре; значение для нового примера читается с его собственного исходника, а не переносится из похожего объекта.



Для «Моих подписок» исходная инструкция подтверждает имя подписки отдельно от имени отчёта, состояние, следующую отправку, канал/подсказку и отписку. В источниках этого блока показан только переключатель «Отчёты». Три вкладки «Отчёты / Источники / AI Hub» из SRC-01 принадлежат избранному; SRC-09 дополнительно показывает там «Метрики». Статус «Включена» — данные подписки; способ рисования тега и кнопок относится к [целевой композиции](<../../target/Требования/Главная.md#рабочая-композиция-подписок--уточнение-пользователя-20-октября>), не к расширению набора исходных атрибутов.




## Значения выбранных примеров



[Значения примеров карточек · JSON](<../Значения примеров карточек.json>) — принадлежащее этому реестру приложение с наблюдаемыми значениями для A/B: пять отчётов (четыре совпадения Гостеприимства и «План-Факт продажи»), CSAT менеджер, S01, паспорт отчёта ID 562 и отдельный паспорт источника UI-06 / S06. Для каждого примера указаны кадр, глубина, известное и неизвестное; `null` не означает пустое значение продукта. Внутренние ключи JSON не задают API.



Неуверенно читаемые сокращения владельцев и инициалы не раскрыты, усечённый домен «План-Факт продажи» не дополнен догадкой. Полное ФИО Ручнова подтверждается паспортом **того же** отчёта. Полный текст описания ID 562 дополнительно транскрибирован по кадру 11:12 в `reportPassport.values.descriptionFull`; исходный фрагмент сохранён отдельно. Короткий excerpt не выдаётся за полный текст, когда используется только он. Упомянутые в описании возможности не объявляются проверенным поведением.



Паспорт источника `sourcePassport` относится к `rewedo_crm_production.public.versions` из 11:23, а списочный `sourceCard` — к `reportcrm20.dbo.dimdate` из 00:52. В приложении отдельно сохранены значения паспорта, подписи/счётчики вкладок и шесть видимых строк из восьми колонок; невидимые строки не дополнены догадкой. «MCP-инструменты 0» — вкладка UI-06, «0 MCP» — счётчик S01; подтверждения отдельного MCP-фильтра списка эти кадры не дают. Типы и размещение UI-элементов принадлежат UI-06, а не схеме полей всех S01.



В `reportPassport.values.businessQuestions` сохранены восемь вопросов по обзору 11:14, отдельно от пользовательских Q&A. Значения общего мастера C не считаются основанием: в его исходных defaults обнаружены смысловые искажения вопросов 5, 7 и 8. `mailingExample` и `homeSubscriptionExample` сохраняют отдельные примеры SRC-06-03, SRC-06-04 и SRC-06-05. Их 3 / 0 / 5 не заменяют 10 / 1 / 8 отчёта ID 562. В настройках листа видны три поиска значений и четыре checkbox «последнее значение»; у «Проекты РГП» поиск в исходном фрагменте отсутствует.



График каждого отчёта виден только в его строке t0040. Точные временные ряды и индивидуальная векторная геометрия не извлечены. Переносить sparkline «Сводного» на остальные отчёты нельзя; наличие графика не доказывает тождество кривых. Значения этого приложения — исторические примеры, не обязательные значения для всех карточек и не дополнение target из образцов C.

14 вариантов и 127 **полевых вхождений** — покрытие выборки, а не 127 разных полей. В это число включены визуальные элементы и действия; оно не подтверждает полный состав П/Ф или базовых фильтров. Новые новости/статистика главной и полные паспорта требуют собственных свидетельств выше, даже если не входили в 14 образцов.



Пять исправлений 19.10.2026 сохранены как результат сверки, а не новые требования: подсветка совпадения R02; роль/подразделение и три показателя участников; иллюстрация/анонс/дата новости; указатель при AI-счётчике 102; зелёный check и красный «!» R01/R02. Разделённое название R02 остаётся одним логическим названием. Не восстанавливать ранние baseline, убирающие эти исправления. Проверка исправлений, передача C.



Рабочая модель поиска — Р: статичный путь и демонстрационные композиции, не источник обязательности атрибутов. Сборка подписи/статуса полного отчёта с MAU списка в рабочей карточке не становится наблюдаемым R01/R02. Исходные требования mini/preview/full не переписываются по факту появления такого образца.
