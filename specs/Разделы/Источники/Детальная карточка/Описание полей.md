# Описание полей источника

Вкладка выбранного источника внутри [детальной карточки](<Контракт.md>). Общие [основания и приоритет](<Контракт.md#1-основания-приоритет-и-граница>), [порядок вкладок](<Контракт.md#4-вкладки-и-раскрывающиеся-поля>), [геометрия и оформление](<Контракт.md#геометрия-и-оформление>) и [единая палитра технических тегов](<Контракт.md#цветовые-группы-тегов>) ведутся каркасом; параметры этой палитры здесь не дублируются. Составная проверка — [критерии карточки](<Контракт.md#7-критерии-приёмки>).

## Геометрия строк

| Зона | Параметры |
|---|---|
| Список полей | При наличии полей между «Об источнике» и первым аккордеоном стоит заголовок «Поля источника». Он выровнен по левому краю колонки, CoFo Sans Regular 14/20, #52698C. От «Об источнике» до заголовка 16 px, от заголовка до первого поля 8 px. Счётчик переданных полей остаётся на вкладке в стиле [B12 tab-count16](<../../../Общие компоненты/Базовые элементы/Счётчик/Контракт.md>). Доступное имя области — «Описание полей источника». Между аккордеонами 8 px. У строки padding 14×16, gap 12. Круг раскрытия 32 слева, иконка 16 px. |
| Имя и признаки поля | Имя Medium 16/20 #101D3B. От имени до первого тега и между тегами 8 px. При обрезке имени или SQL-типа доступна подсказка с полным текстом. SQL-тег имеет максимальную ширину 112 px. На ширине списка до 620 px в шапке остаются SQL-тип и обязательность, а максимальная ширина SQL-тега уменьшается до 88 px. До 400 px она составляет 64 px. Обобщённый тип и признак ключа доступны в раскрытом теле. Счётчик метрик остаётся справа. |
| Список метрик в теле | По одному названию на строку в порядке данных. Минимальная высота 32 px, длинное название переносится, нижних разделителей нет. Название и декоративная иконка внешнего перехода окрашены в #006BDB. Иконка 14 px слева, отступ до текста 8 px. Её центр находится на одной вертикальной оси с кругом раскрытия, а иконка и текст центрируются внутри строки. При наведении вся строка получает фон боковой навигации (`--sidebar-surface`, #F3F4F9) со скруглением 8 px. Список называется «Связанные метрики» для вспомогательных технологий. Строки сохраняют семантику списка, клик не ведёт на другую страницу. |

## Данные, раскрытие и начальное состояние

Количество колонок источника и количество переданных строк — разные значения. Исходный кадр rewedo подтверждает метаданные о восьми колонках и первые шесть строк в таблице ниже. Текущий демонстрационный набор дополняет его двумя явно обозначенными примерами. Для внешнего источника с неполным списком сохраняются переданные строки; отдельная пагинация или кнопка догрузки из расхождения количеств не следуют.

| Поле | SQL-тип | Обобщённый тип | Допустимость null | Ключ | Подтверждённый счётчик связанных метрик |
|---|---|---|---|---|---|
| id | INTEGER | NumberType | Required | Key | 0 |
| item_type | VARCHAR | StringType | Required | Not key | 0 |
| item_id | BIGINT | NumberType | Required | Not key | 0 |
| event | VARCHAR | StringType | Required | Not key | Не установлен, в макете «—» |
| whodunnit | VARCHAR | StringType | Nullable | Not key | Не установлен, в макете «—» |
| object | TEXT | StringType | Nullable | Not key | Не установлен, в макете «—» |

Справа показываются «Метрики» и синий счётчик в стиле активной вкладки, если передан непустой список связанных метрик. Число равно длине этого списка. Если список пуст или не предоставлен, надпись и счётчик скрыты. Круг раскрытия находится слева. При раскрытии известный ноль и недоступность различаются текстом.

В первоисточнике `reportcrm20.dbo.dimdate` у `Date` 12 метрик, а у `DateKey`, `FullDate` и `FullDateUSA` подтверждён ноль. SRC-17 · SRC-18 · SRC-28.

В локальной демонстрации `DateKey` и `FullDate` остаются пустыми, а `Date` показывает 12 подтверждённых названий в исходном порядке. Остальные поля этой карточки, включая `FullDateUSA`, получают по 3–7 авторских примеров для заполненного состояния. Набор `dwh2crm.ref.dimdate` содержит демонстрационные связи для `date_key` и `calendar_year`. [Данные примера](<../assets/Срез 9 ноября/sources-example.json>).

Начальное состояние: «Об источнике» раскрыт; все поля свёрнуты. Каждое раскрытие независимо; режим «только одна открыта» не вводится. В текущем frontend-примере раскрытая область при достоверном count=0 показывает «Связанные метрики не найдены». При неизвестном count и отсутствии переданного списка показывает «Сведения о связанных метриках не предоставлены». Это обозначение границы локальных демоданных, не обещание загрузки backend. Реальные метрики, ссылки или формулы для этих полей не придумываются.

У каждого из девяти источников каталога есть собственный список аккордеонов. Длина списка равна числу колонок: 34/33/20/12/18/24/15/10/8. В `rewedo_crm_production.public.versions` шесть полей из таблицы дополнены демонстрационными `created_at` и `object_changes`. В `reportcrm20.dbo.dimdate` первые четыре поля подтверждены кадрами, остальные поля демонстрационные. Для других источников словари авторские. Источник данных хранит перечень демонстрационных полей.

Используется общий Accordion, включая Enter/Space, корректные aria-expanded/aria-controls, недоступность закрытого содержимого для фокуса, независимые состояния и анимацию. [Общий владелец](<../../../Общие компоненты/Аккордеон/Контракт.md>) определяет 320 ms раскрытия/стрелки, текущую кривую, reduced motion и hover рамки. В потребителе эта механика не копируется.

## Семантика технических признаков

Цвет обозначает технический признак, а не новое состояние загрузки/валидации. SQL-тип и обобщённый тип не объединяются в одну метку. Required не означает ошибку, Nullable не означает предупреждение о качестве, Key не означает подтверждённую карточку.

## Граница данных выбранного источника

В локальном demo-наборе каждая из девяти записей имеет собственный полный словарь полей согласно уточнению выше. Summary-идентичность, количество колонок и известность счётчиков сохраняются; новые словари не меняют историческую карточку каталога на производственную схему. Сведения rewedo не назначаются другим источникам в качестве fallback. Для внешнего подменяемого producer, не передавшего поля, сохраняется честное сообщение об отсутствии сведений. Технический ID demo-записи и query-параметры принадлежат реализации прототипа; они не становятся backend-контрактом.
