## Граница и данные

Паспорт показывает выбранный отчёт, его название и сведения из того же объекта, который открыт из списка/поиска. Каждый новый переход к отчёту из списка, поиска или связанного объекта начинает с «Обзора»: обработчик открытия явно задаёт reportTab=overview, даже если в URL списка остался другой reportTab. При смене вкладки ID отчёта сохраняется. Состояние вкладки записывается в параметр reportTab; перезагрузка и явная прямая ссылка сохраняют выбранный таб, история браузера восстанавливает прежний контекст. Крошка «Отчёты» возвращает в сохранённый список с его параметрами; при прямом входе без сохранённого списка — в каталог отчётов.

UI получает подменяемый источник ReportDetailSources: read(reportId), metrics, mailings и необязательный usage. Его тип ведётся в [source.ts](<../../../../references/implementation/features/report-detail/source.ts>); это информация для UI, а не утверждённый серверный API. Полный обзор, четыре слайда, согласованные пять источников и граф Paper07, две рассылки и пример использования связаны только с demo-report-summary. Другим объектам это содержимое автоматически не присваивается. Связанные метрики имеют собственный источник и набор для двух явно указанных demo-ID. Отсутствие примера не означает отсутствие данных в продукте.

**Граница замены данных RM-13:** текущие `ReportDetailContent`/`ReportOverviewContent` не передают видимый ID, пояснение шапки, расписание обновления и персональные сведения. `ReportDetail`/`OverviewTab` выводят562 и фиксированные сведения/людей только в доступном fixture-состоянии; текущий producer ограничивает его одним `demo-report-summary`. При добавлении другого содержимого эти значения нельзя переносить по одному признаку available. До определения входов UI для собственных метаданных, ответственных и отсутствующих значений готовность этого источника к замене вне точного fixture ограничена. Серверная схема, новые люди и business-ID здесь не назначаются.

Текстовые метки Обзора/сведений подключают [B13 report-token12 / report-role12](<../../../Общие компоненты/Базовые элементы/Тег/Контракт.md>); line-height и цвет нейтрального token наследуются от контекста. Во вкладке связанных метрик B13 metric-related24 сохраняет отдельный фон типа. Это наблюдаемые bindings текущего кода, а не новый Figma-binding всей вкладки. Значения/связи/права и таблицы обычного текста остаются у паспорта; платформенные метки графа не назначены B13 автоматически.

### Вопрос пользователя

П4-03 разделяет поисковое однострочное [поле B02](<../../../Общие компоненты/Базовые элементы/Поле ввода/Контракт.md>) и поля паспорта. В текущей demo-форме вопроса [OverviewTab](<../../../../references/implementation/features/report-detail/overview/OverviewTab.tsx>) использует textarea; это наблюдение реализации B03, а не назначение всем текстовым полям многострочности или общего оформления. Успех demo не добавляет вопрос в реальный список или счётчик «Мои вопросы».

Срез источников, активный/обычный рендер, результаты и ограничения сверки. Hover заголовков секций определяется единым [контрактом аккордеона](<../../../Общие компоненты/Аккордеон/Контракт.md#общая-стрелка-и-hover--уточнение-3-ноября>).

Это визуальные варианты корпуса, не общие результаты действий. Локальная закладка, сообщение ограничения редактирования и внешнее открытие сохраняют установленные выше границы. Кнопки вопроса/рассылки не получают визуальный binding к B01 только из наличия такого действия.

Белые карточки, панель контролов связанных метрик, внешние углы её табличных строк и общие аккордеоны во всех вкладках следуют [единому правилу радиуса карточек](<../../../../context/target/Требования и границы.md#единый-радиус-белых-карточек--решение-3-ноября-2026>). Локальные адаптивные правила источников ведёт [владелец вкладки](<Источники данных.md>). Это адаптивные правила реализации; эталонов иных ширин в секции нет.
