Страница размещает общий поиск в хедере над существующим каркасом главной. Поиск раскрывает выдачу поверх контента; выбор типа внутри поиска сам по себе не меняет текущий раздел бокового меню. Назначение05А — паспорт выбранного отчёта, а не одиннадцатый поисковый экран.

Фоновый список имеет собственную область прокрутки/пагинацию; его внутренности принадлежат главной. Не превращать раскрытие поиска в замену фонового списка или его прокрутки.

Эти конфигурации окружения не вводят новый breakpoint или автоматическую формулу числа карточек; полная адаптация главной у другого владельца.

## 6. UI-входы/выходы страницы и пределы демо
| Граница | Семантическая информация | Ответственность |
|---|---|---|
| Окружение → поиск | Конфигурация показа,текущий query,набор выбранных типов,данные/подсветка результатов | Роли и состояния — у общего компонента; producer выдачи не проектируется этой страницей. |
| Поиск → окружение | Намерение уточнить query/типы,раскрыть больше результатов,выбрать конкретный объект | Форма UI-намерения не задаёт endpoint,права или алгоритм ранжирования. |
| Выбор → назначение | Идентичность выбранного объекта; показанный пример отчёта | Только структурно подтверждённая связь к05А. |
| Закрытие/clear → текущая страница | Закрытое/пустое локальное состояние поиска | Долговременное хранение и внешние фильтры не определяются по snapshot. |

Фон главной — контекст макета, не результат поиска. Не фильтровать его карточки только из-за изменения query в выпадающем поиске без отдельного решения владельца сквозного сценария. Результаты,подписи и totals в кадрах — fixtures; они не являются бэкенд-контрактом. Наличие типов без показанного наполнения не подтверждает отсутствие данных у этих сущностей.

## 7. Приёмка и ограничения
1. Открыть каждый из10точных кадров и сверить его с общей картой состояния; не выбирать эталон по одному имени Results.
2. Для1440 и1920 проверить границы страницы,anchor поля/выдачи,ширину280 боковой области и доступную правую ширину по§3. Стили дочерних компонентов сверять по их владельцам.
3. Сравнить materially distinct композиции с указанными полными PNG при том же viewport,query иfixture. Новые PNG не заменяют внутренние эталоны общего поиска.
