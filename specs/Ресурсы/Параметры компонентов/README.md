# Формат и проверка параметров компонентов

Один YAML-файл параметров у владельца семейства; Markdown ведёт назначение, анатомию, механику, условия, ограничения и точные эталоны. Данные конкретного применения и семантика Apply остаются у потребителя. Смена формата не создаёт новые продуктовые требования и не подтверждает улучшение генерации.

## Рабочее расположение и перенос

Единственная [схема параметров](<schemas/component-parameters.schema.json>) генерируется [явными определениями](<build_parameter_schema.py>): редактируемый источник типов — генератор, JSON является его результатом. Формат, схема, генератор и проверяющий инструмент находятся в этом общем ресурсе; старой рабочей копии нет. Это проектный источник формата параметров, а не ещё один контракт поведения.

У нового семейства целевые имена: Контракт.md и Параметры.yaml. В Markdown можно пояснять смысл параметра и ссылаться на ключ, но нельзя независимо повторять таблицу тех же чисел. Ключи component/variant/state/parameter — стабильные kebab-case идентификаторы; отображаемые подписи сохраняют русский язык продукта. Пути внутри YAML — относительно корня передаваемого пакета/проекта и только к существующим файлам. Плановый путь ещё не созданного владельца не является допустимой зависимостью готового контракта.

## Модель

| Часть | Ответственность |
|---|---|
| component | ID семейства, название, действующий Markdown-владелец и статус approved-target / observed-source / example-only; реализация в коде этим не подтверждается |
| sources | Точные документы, ресурсы, DS-источники и Figma URL с nodeId, статусом и срезом. Сохраняется буквальный URL, а не автоматически перестроенная ссылка |
| tokens | Именованные ссылки на канонический источник и locator; второе редактируемое literal-value здесь запрещено |
| base | Общие типизированные параметры и обязательные ссылки на источники |
| variants | Подтверждённые именованные варианты, параметры и при необходимости состояния; каждый уровень имеет источник |
| dependencies | Только реально существующие дочерние контракты, источники DS или внешние владельцы; без самоссылки и повторного ID |

Размер содержит число и единицу px/rem/em/%; угол — число и deg. Отрицательные размеры допустимы на уровне типа для подтверждённых смещений, а допустимость конкретного padding/height проверяется по контракту. Есть отдельные типы number/integer/opacity, boolean, string, font-family и font-weight. Значение цвета — hex6/hex8 либо точные числовые каналы sRGB; нельзя молча округлять исходный RGB в hex. Наличие font-family/weight не доказывает наличие соответствующего файла: это проверяется по владельцу шрифтов и подключению отдельно.

Token-параметр содержит ref и expectedType; проверяется наличие ссылки и совпадение её типа. Фактическое значение токена остаётся у канонического источника. Источники параметров наследуются от ближайшего base/variant/state; отдельное sourceRefs у значения уточняет происхождение. В примере источники Figma явно unverified-live: валидная ссылка с nodeId не доказывает актуальность живого макета.

Для одного выбранного варианта и названного состояния значения объединяются base → variant → state. Более конкретное значение заменяет тот же ключ; его эффективный тип сохраняется. Это порядок разрешения параметров, а не придуманный приоритет поведения hover/error/disabled. Комбинации интерактивных состояний и результат действий определяются Markdown-владельцем; схема сама их не устанавливает.

## Проверка

[Пример селекта](<examples/select-parameters.yaml>) имеет статус example-only: это fixture схемы, не источник параметров реального компонента и не второй источник параметров продукта. Данные ширины и высоты взяты из существующего владельца для проверки точного чтения; применять их ко всем интерфейсам без варианта нельзя.

[Проверяющий инструмент](<check_parameters.mjs>) выполняет реальный разбор YAML 1.2, отвергает ошибки/предупреждения и дубликаты ключей, проверяет JSON Schema draft-07, затем существование локальных файлов, source/token/dependency references, совпадение nodeId с URL и сохранение типа при overrides. Схема записана в JSON как метаописание допустимых YAML-данных; это не экспорт компонентной конфигурации в JSON.

Для запуска нужен Node и библиотеки yaml/ajv указанных в [манифесте инструмента](<parameter-tools.package.json>) версий в отдельном доступном runtime. Это зависимости проверки документации; package.json приложения и его зависимости не меняются. Параметр --runtime указывает каталог с этими установленными библиотеками; его локальный путь не записывается в продуктовые контракты. Корень проверяемого пакета обязательно передаётся через --root; инструмент не угадывает его по глубине расположения файла.

Пример вызова из корня проекта (RUNTIME — выбранный каталог инструмента):

```text
node "Документация ／ Documentation/Целевое решение ／ Target/Спецификации интерфейса/Ресурсы/Параметры компонентов/check_parameters.mjs" --root . --runtime RUNTIME --self-test --report REPORT
node "Документация ／ Documentation/Целевое решение ／ Target/Спецификации интерфейса/Ресурсы/Параметры компонентов/check_parameters.mjs" --root PACKAGE_ROOT --runtime RUNTIME --file PATH_TO_PARAMETERS
```

Положительные и намеренно повреждённые данные проверяются одной схемой. Итог печатается; необязательный --report сохраняет подробности в выбранном рабочем месте вне нормативного ресурса. Синтаксис, типы и ссылки не заменяют проверку полноты, источника, смысла состояния, соответствия изображениям и маршрута применения. Unknown правила остаются явными ограничениями, а не значениями, придуманными для прохождения схемы.

## Адресное чтение без копий значений

[Инструмент чтения](<read_context.mjs>) выводит выбранную запись JSON либо один вариант и одно названное состояние YAML. Канонические файлы не изменяются. Вывод — временное представление для чтения, а не второй редактируемый источник.

```text
node read_context.mjs --file PARAMETERS.yaml --runtime RUNTIME --variant VARIANT --state STATE --keys field-height,glyph-open-angle
node read_context.mjs --file DATA.json --pointer /data/profiles --field id --equals EXACT_ID
node read_context.mjs --file PACKAGE.json --pointer /origins --field path --equals EXACT_PACKAGE_PATH
```

Имена варианта/состояния и путь JSON берутся из действующего контракта, а не из примера команды. `--state` и `--keys` необязательны. Для JSON `--pointer` обязателен; `--field`/`--equals` выбирают ровно одну запись массива и отвергают неоднозначный или отсутствующий ID. Число0, null и типы сохраняются. Для YAML порядок — base → выбранный variant → выбранный state; вывод содержит определения использованных токенов, происхождение значений, источники слоёв и зависимости. Комбинации состояний этим порядком не изобретаются. Ссылки токенов на внешние определения остаются ссылками с locator; чтобы получить значение, читать указанного владельца, включая его режимы/ограничения.

Для каталогов дизайн-системы применять точный ID/путь и проверять alias-зависимости выбранной записи. Методические документы проектирования в Figma и журналы приёмки открываются для конкретного спорного основания; они не задают обязательный порядок каждой генерации frontend. Саму дизайн-систему этот инструмент не редактирует.
