# Состояния и действия поиска

Действующие переходы принятой реализации [общего поиска](<Контракт.md>). Назначения и данные — в контракте, вид и параметры — в [«Вид»](<Вид.md>), точные условия съёмки — в [кадрах](<Источники вида.md#кадры-принятой-реализации>).

## Поле и выдача

Поле имеет роль `combobox`. При наличии совпадений оно связано с сеткой результатов (`grid`). Каждое совпадение находится в собственной строке, а переход к месту и кнопка паспорта доступны как отдельные действия. При перемещении стрелками из поля строка получает состояние выбора. Проверяйте активную строку внутри сетки.

| Состояние | Событие | Наблюдаемый результат |
|---|---|---|
| Поле закрыто | Клик или получение фокуса полем | Выдача открывается. Пустой запрос показывает «Начните поиск по каталогу» и доступные типы |
| Поле доступно | Изменить запрос | Выдача открывается. Сохранённая позиция выдачи и активная строка сбрасываются. При совпадениях показаны группы и футер, при отсутствии — «Ничего не найдено» |
| Выдача открыта | Нажать чипс | Добавить или убрать только этот тип. Выбор доступен до ввода. После снятия последнего типа поиск снова охватывает все типы. Запрос сохраняется, активная строка сбрасывается и показывается первая порция |
| Есть текст запроса и выбран хотя бы один тип | Нажать «Сбросить выбор типов» | Снимается весь выбор типов. Запрос сохраняется, выдача снова начинается с первой порции по всем типам |
| Выдача открыта | Escape | Выдача закрывается, фокус возвращается в поле, активная строка сбрасывается. Запрос и выбранные типы сохраняются |
| Выдача открыта | Нажать за её пределами, вне поиска | Выдача закрывается. Запрос и выбранные типы сохраняются, клик действует на свой элемент |
| Поле содержит текст | Нажать «Очистить запрос» | Поле очищается и сохраняет фокус. Выдача закрывается, активная строка и сохранённая позиция сбрасываются, выбор типов сохраняется. Метка и переключатель совпадений на открытой странице исчезают |
| Есть результаты | ↑ или ↓ в поле | Выдача открыта, активная строка перемещается в пределах выдачи без перехода через край и выводится в видимую область |
| Выдача открыта, активна строка с назначением | Enter в поле | Выполняется основное действие именно активной строки |
| Выдача открыта, активной строки с назначением нет | Enter в поле | Ничего не открывается, выдача остаётся доступной |
| Активна строка с назначением, фокус в поле | Tab вперёд | Фокус переходит на основную кнопку активной строки. При наличии кнопки паспорта → переводит фокус на неё, ← возвращает на основную кнопку. Enter активирует кнопку в фокусе |
| Запрос введён, результатов нет, отчёты входят в область поиска, demo-данные отчётов ожидаются или недоступны | Получен статус demo-источника | «Загрузка примера…» или «Не удалось получить данные» с пояснением «Демонстрационный источник отчётов недоступен.» |

При непустом запросе каждый чип показывает число совпадений своего раздела до фильтрации и деления на порции. Раздел без совпадений показывает 0. Пока источник отчётов загружается или недоступен и совпадений отчётов ещё нет, счётчик отчётов скрыт. При пустом или пробельном запросе скрыты счётчики, очистка поля и кнопка общего сброса типов. [Браузерная проверка](<../../../references/verification/tests/search.spec.ts>).

## Порционная выдача

Первая порция содержит до 15 результатов суммарно по группам. В футере справа указано, сколько строк показано из полного локального результата. Если остаются совпадения, слева доступно «Показать ещё N», где N — до 15. Нажатие добавляет следующую порцию в том же порядке и при необходимости прокручивает список до первой новой строки. Фокус остаётся на кнопке, пока есть следующая порция. После последней порции фокус переходит к основному действию первой новой строки или в поле поиска, если действие отсутствует.

Группа появляется, когда показана хотя бы одна её строка. Смена запроса или выбора чипсов возвращает первые 15 результатов и начало списка. При повторном открытии того же запроса раскрытые порции сохраняются. Прототип берёт порции из локального набора. [Браузерная проверка порций и фокуса](<../../../references/verification/tests/search.spec.ts>).

## Переходы и фокус

- При успешном выборе строки выдача закрывается. Запрос и выбранные типы сохраняются. Окружение открывает раздел, вкладку или страницу списка и раскрывает нужное содержимое. После появления совпадения в видимой области фокус переходит на содержащую его кнопку или ссылку, а при их отсутствии — на сам выделенный фрагмент.
- При выборе совпадения в описании Навигатор проверяет его видимость в текущем виде списка. Обрезанное совпадение открывает паспорт, если он доступен, и получает подсветку в полном описании. В истории появляется один переход. Для показателя, у которого полное определение сформулировано иначе, совпавшее описание из каталога выводится в блоке полного описания.
- При выборе круглой кнопки выдача закрывается, фокус ставится на заголовок паспорта. Действие кнопки не запускает основное действие строки. Переключатель совпадений для этого способа перехода не показывается.
- Повторный клик в поле открывает выдачу с сохранённым запросом и типом. Если с момента выбора запрос и тип не менялись, восстанавливаются активная строка и прокрутка выдачи. Возврат к исходному адресу через браузерную историю после перехода из поиска открывает выдачу и возвращает фокус в поле. Отдельной кнопки «К результатам поиска» нет.
- Смена найденного результата заменяет активное совпадение. Переход на другую страницу без поискового назначения убирает метку и переключатель. При переходе с найденного поля на вкладку источника «Связанные отчёты» они скрыты.
- Удаление всего текста вручную или кнопкой «Очистить запрос» сразу снимает метку и скрывает переключатель. Запрос из одних пробелов считается пустым. Текущая страница и вкладка сохраняются. Повторный ввод текста сам по себе не восстанавливает метку. Для новой метки нужно выбрать результат.
- При правке, после которой запрос остаётся непустым, метка предыдущего перехода сохраняется. Переключатель доступен только для исходного текста этого перехода после нормализации.

## Переключатель совпадений

| Состояние | Событие | Наблюдаемый результат |
|---|---|---|
| Выбран результат через строку, на странице два или более совпадения исходного запроса, выдача закрыта, текст поля после нормализации совпадает с запросом перехода | Назначение открыто | В поле слева от крестика видны ←, номер вхождения и общее число, →. Начальный номер соответствует выбранному месту. На странице одна активная метка |
| Переключатель показан, соседнее совпадение существует | Нажать ← или → мышью либо активировать клавиатурой | Активная метка переходит к соседнему вхождению и прокручивается в область видимости. Счётчик обновляется. Фокус остаётся на кнопке, выдача остаётся закрытой, адрес и фильтры не меняются |
| Достигнуто первое или последнее вхождение | Активировать стрелку за границу | Соответствующая стрелка обозначена недоступной. Метка и счётчик остаются на месте |
| Одно вхождение или нет доступных совпадений, выдача открыта либо поле содержит другой запрос | Изменение состояния | Переключатель скрыт |

Единица переключения — отдельное неперекрывающееся вхождение в индексируемом тексте текущего списка, открытого паспорта или вкладки. Порядок — порядок записей в наборе текущей поверхности, затем порядок индексируемых полей и позиция внутри текста слева направо. Для отчётной таблицы используется порядок отображаемых групп и строк. Два вхождения в одном определении считаются отдельно. Варианты написания одного поля одной записи не удваивают счётчик. Совпадения на других страницах списка и в других разделах в счётчик не входят. Это независимый счётчик, он не ограничивается выбранным чипсом глобальной выдачи.

### Подсветка Default
Первая строка кадра04 связана с505:5994 **State=Default**, но имеет локальный фон RGB(0.9,0.95,1). Это демонстрируемая подсветка, не новый вариант Selected. Базовый Hover505:6008 имеет другой серый фон. В реализации визуальная подсветка, hover и намерение выбора должны различаться; конкретная продуктовая семантика голубого выделения за пределами этого кадра не установлена.

В этом экземпляре название содержит синий фрагмент «отчёт», метаданные тоже имеют локальные диапазоны синего текста. Не выводить алгоритм поиска или обязательную подсветку всех совпадающих букв из сохранённых styled ranges. UI получает согласованные диапазоны/оформление вместе с данными либо следует отдельно установленному правилу. Точные цвета и эталон — в «Вид».

### Набор типов в семействе
В основном ряду показаны «Отчёты», «Метрики и показатели» (на экранных экземплярах — «Метрики»), «Источники», «Бизнес-словарь», «AI Hub» и «Ещё» с отдельной иконкой направления. В дереве семейства также предусмотрены «Справочники ИС» и «Вопросы и ответы», скрытые в проверенном основном ряду. Этот набор контролов не подтверждает готовую выдачу всех семи типов. Для бизнес-словаря/AI Hub есть демонстрационные переходы к NoResults; это не правило, что у этих типов всегда нет данных. Варианты групп результатов подготовлены для отчётов, источников и метрик.

Дополнительная поверхность Д6 ·1704:71378: открыто меню «Ещё», чипс active с иконкой вверх; сохранены выбранные Отчёты/Источники и исходная выдача Д2. [Полный эталон](<../../../references/navigator/Изображения/d6-more-open.png>).

## 3. Локальные действия

Таблица ниже относится к исходным макетам. Действующее поведение прототипа описано в начале документа.
| Предусловие → действие | Видимый результат / намерение | Что подтверждено и граница |
|---|---|---|
| Closed → нажать поле | Открыть поиск | Семейства содержат состояния и реакции открытия; семантика — раскрыть компонент, не выполнить backend-запрос. |
| Focused → ввод текста | Показать текущий query; запросить относящуюся выдачу | В Figma показаны готовые тексты. Реальное редактирование, задержка и вычисление выдачи не проверены. |
| Focused → Enter | Готовый Results | Настроена CHANGE_TO506:4792; это демо-переход, не доказательство реального поиска по Enter. |
| Открытая выдача → выбрать тип | Уточнить набор типов, показать относящиеся группы | [B08 search-type32](<../Базовые элементы/Чипс/Контракт.md>) передаёт активацию типа; есть варианты одиночного и множественного выбора. Произвольная логика сочетаний неизвестна. |
| Открытая выдача → «Ещё» | Доступ к дополнительным типам | Показан Д6: компактное меню двух дополнительных типов; геометрия и down/up-иконки у владельца «Вид». Д2↔Д6 имеют настроенный NAVIGATE; Present не проверялся. Поведение произвольных сочетаний типов не устанавливается этим показом. |
| Есть выбранные типы → «Сбросить фильтры» | Намерение снять относящееся ограничение типов | Контрол виден при наличии выбранных типов, включая одиночный Reports, и скрыт без выбора; не обобщать сброс на query, сортировку и внешние фильтры. |
| Compact → действие раскрытия футера | Expanded; больше строк, часть внутри scroll | Реакции переключают готовый вариант; totals — демонстрационные. |
| Строка → hover | Вариант строки Hover505:6008 | ON_HOVER / MOUSE_LEAVE между505:5994/505:6008. Это не открытие паспорта. |
| Конкретный «Сводный отчёт Гостеприимства» → click | Намерение открыть этот объект; структурный пример →1056:22923 | NAVIGATE настроен на строке кадра04; название назначения совпадает. Present не проверен. Для остальных строк не назначать этот же паспорт. |
| Results/NoResults → «Очистить запрос» | Исторически показан пустой Focused/BeforeInput | CHANGE_TO Focused относится к старому срезу. По прямой правке пользователя3 ноября в React-прототипе крестик серый, очищает query и закрывает dropdown; новый смысл ведёт контракт. |

Пустое поле не показывает Clear; заполненные Results/NoResults показывают. Окружение должно получать намерение выбора вместе с идентичностью объекта, а не извлекать объект из визуального названия. Дальнейший переход, права и открытие внешнего отчёта вне этого компонента.

В двух исходных одиночных примерах кнопка сброса показана после исправления, но новые реакции Figma тогда не добавлялись. Это историческое ограничение демонстрации. Текущий reset типов работает по таблице выше и не очищает query/внешние фильтры.

## 4. Данные разных типов
Группа отчётов использует краткие роли домен/платформа/мастер-система. Группа источников и группа метрик используют свои роли из реестра. Видимые подписи и ordering берутся из предоставленного набора, не из названия Figma State. Compact в мастере содержит по2 строки трёх типов; Expanded и ThreeTypes —4/6/5. Это fixtures.

Футер показывает предоставленную подпись количества. Его пример «Показано6 из30» не задаёт нормативный размер порции6, общий total30 или способ вычисления. Для одного типа в мастерах показаны4/4,6/6,5/5; экранный Reports сокращён до «Показано4 отчёта». Генерация не должна заменять локальную подпись мастерной.

## 5. Приёмка поведения и границы
Историческая проверка макета охватывала Clear, dropdown, чипс, группу, подсветку, футер и структурный переход к одному показанному паспорту. Действующий маршрут приёмки — [выше](#приёмка-принятой-реализации).

Исходные визуальные состояния не подтверждают права, debounce, production-асинхронность/retry, произвольное количество объектов или screen reader. Текущие active-index клавиши и native pending/error описаны выше как наблюдаемые demo-механики; наличие Escape в Figma не заменяет их функциональную проверку. Не переносить эти наблюдения в неизвестные интеграционные правила.

[Контракт B18](<../Базовые элементы/Пустое состояние/Контракт.md>) и [YAML search340](<../Базовые элементы/Пустое состояние/Параметры.yaml>) владеют только иллюстрированной внутренней областью BeforeInput/NoResults.
