Актуализация параметров и визуальных эталонов: 2 ноября 2026. Исторические даты подготовки ниже сохраняют свой срез; параметры и PNG проверяются по обновлённым манифестам.

## 1. Назначение и границы
Компонент позволяет ввести запрос, задать область поиска по типам объектов, увидеть сгруппированные результаты и передать намерение выбора конкретного объекта. Состоит из поискового поля, раскрываемой выдачи, выбора типов, групп, строк, футера и показанных пустых состояний.

Компонент занимает предоставленную хедером ширину; выдача накладывается на содержимое ниже. Контракт общего хедера/бокового меню принадлежит соседнему владельцу по [карте спецификаций](<../../Обзор.md>). Их состав и маршруты здесь не воспроизводятся. Детальный паспорт отчёта — получатель намерения выбора, его внутренности здесь не описываются; владелец — [R-01](<../../../context/flows/reports.md#r-01-изучить-полный-отчёт>).

Источники: [секция навигатора](https://www.figma.com/design/lnOcWh4ElGkhppWe6Kn5AA/Untitled?node-id=524-5664), семейства [поле/раскрытие](https://www.figma.com/design/lnOcWh4ElGkhppWe6Kn5AA/Untitled?node-id=506-6397), [выдача](https://www.figma.com/design/lnOcWh4ElGkhppWe6Kn5AA/Untitled?node-id=505-8190), [строка](https://www.figma.com/design/lnOcWh4ElGkhppWe6Kn5AA/Untitled?node-id=505-6022). Используются актуальные нормализованные имена. Исторические proof не заменяют этот срез.

## 2. Владельцы правил
| Владелец факта | Локальное следствие для компонента |
|---|---|
| [Требования: границы редизайна](<../../../context/requirements.md#границы-и-свобода-редизайна>) | Общие обязанности поиска не сводятся к нескольким демонстрационным типам/числам этого макета. Не добавлять отсутствующие реализации по одному брифу. |
| [Навигатор — основа ТЗ](<../../../context/navigator-foundation.md>), [маршрут путей](<../../../context/flows/README.md>) | Сквозной выбор глубины открытия и сохранение контекста ведутся там. Здесь только локальная поверхность и явно подтверждённый демонстрационный переход. |
| [Состав карточек](<../../../context/data-attributes.md>) | Смысл атрибутов зависит от типа объекта. Краткая строка поиска не подменяет полный паспорт. |
| [Рабочая DS](<../../../context/design-system.md>) | Figma-экземпляры и токены — визуальные зависимости. Соответствие конкретной версии React-компонента не установлено. |

Актуальные кадры показывают конкретный выбор отчёта → паспорт. В более ранней основе ТЗ остаётся вопрос прямого клика/перехода в раздел; данная порция не разрешает его автоматически для всех объектов. Это граница спецификации, а не новый маршрут.

## 3. UI-данные и намерения
Ниже семантические данные для отображения, не backend DTO и не предложение API.

| Роль данных | Что компоненту необходимо | Ограничение |
|---|---|---|
| Запрос | Текущий текст; отдельно пустой запрос/placeholder | Алгоритм, задержка и порог поиска не определены. Примеры «отчёт», «Сводный», «о», «гост» не являются правилами поиска. |
| Типы | Идентификатор и видимая подпись типа; выбранность; видимость в основном ряду/дополнительных типах | Показаны разные сочетания. Возможность произвольного сочетания всех типов и права требуют внешнего правила. |
| Группы | Тип, подпись, иконка, строки, подпись количества | Число группы и счётчик футера поступают с выдачей. Не выводить глобальный total из числа отрисованных DOM-строк. |
| Результат | Устойчивая идентичность объекта для выбора; тип; название; видимые метаданные по типу; необязательные заданные диапазоны подсветки | В Figma идентичность одного примера подтверждена текстом/маршрутом; формат продуктового идентификатора не задан. |
| Метаданные | Для показанного отчёта — домен, платформа и мастер-система; источника — собственные роли; метрики — собственные тип/статус | Невидимые exposed properties не становятся дополнительными видимыми полями. ФИО и полные исходные описания не нужны общему компоненту. |
| Пустая выдача | Различение «до ввода» и «нет совпадений» | Не является доказательством отсутствия объектов в системе, отказа доступа или ошибки. |
| Уточнение поиска | Намерение изменить запрос/набор типов | Производитель выдачи вне компонента; endpoint, права и вычисление результатов не назначаются. |
| Выбор результата | Намерение открыть именно выбранный объект | Принимает маршрутизирующее окружение. Не открывать один пример паспорта для всех строк. |
| Раскрытие выдачи | Намерение показать больше относящихся к текущему запросу результатов | Compact/Expanded в макете — демонстрационные наборы; это не серверная пагинация. |

Иллюстрации/сообщения, описание состояния и count strings принадлежат UI. Компонент не вычисляет предметную релевантность, права и устойчивое хранение по данному контракту. Заменяемые fixtures допустимы только как явно обозначенный механизм демонстрации; контент fixtures не закрепляется как бизнес-данные.

## 4. Приёмка первой порции
1. Проверить соответствие трём семействам и нормализованным частям по таблице «Вид». ID и состояние важнее похожего имени.
2. Сравнить каждое описанное состояние с его PNG при тех же размерах компонента и окна, том же запросе, выбранных типах и демонстрационном наборе. Если рабочие данные отличаются, отдельно проверить компоновку с ними; такое сравнение не заменяет проверку по эталонному набору. Мастер и локальный override сравнивать с разными эталонами.
3. Проверить ширину поля/выдачи, привязку y36, внутренние отступы, границу прокрутки, скругления, типографику и цвета по «Вид», а не оценкой изображения.
4. Воспроизвести таблицы состояний и локальных действий из «Состояния». Hover не должен подменять намерение выбора; clear — скрыт в показанном пустом поле.
5. В отчётной строке показывать домен один раз по Домен#700:0; не выводить скрытые описание, label и значение2 только потому, что они существуют как exposed properties.
6. При клике демо-отчёта сохранять идентичность выбранного объекта. Неподтверждённые маршруты, backend и персистентность не считать пройденными по этому примеру.
7. Проверить доступность файлов visual-manifest, всех PNG/SVG и ссылок владельцев. Скриншоты не заменяют шрифт/иконки реализации.

**Не установлено:** окончательное поведение всех объектных кликов и «Все результаты в разделе», backend поиска/ранжирование, произвольные сочетания типов, права, URL/межсессионное хранение, фокус после закрытия/возврата, runtime keyboard navigation, loading/error/retry. Эти состояния не добавляются по догадке. Композиция показанного пути и граница назначения описаны в [контракте раздела «Навигатор»](<../../Разделы/Навигатор/Контракт.md>); правила иных переходов этим контрактом не добавляются.
