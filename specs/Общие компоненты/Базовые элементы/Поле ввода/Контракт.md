# Поле ввода и поле поиска

Общий владелец B02 для двух подтверждённых применений однострочного поиска. [Параметры.yaml](<Параметры.yaml>) ведёт типизированные значения и происхождение; этот контракт — границу, анатомию и условия применения. Выделение П4-03 не меняет принятые действия поиска или форм. [Формат и проверка YAML](<../../../Ресурсы/Параметры компонентов/README.md>) общие с остальными базовыми элементами.

## Граница и маршрут

Для конкретного применения читать родительский блок → выбранный вариант B02 → YAML и нужный SVG/шрифт. Доступ ко всем разделам не требует загрузки всех их полей в контекст.

| Факт | Владелец |
|---|---|
| Внутренний корпус поля, отступы, типографика, рамка, размещение glyph и подтверждённые визуальные различия | Этот контракт и YAML |
| query/value, placeholder, label/доступное имя, открытость составного блока, наличие trailing action | Применяющий блок |
| Где искать, какие значения отбирать, сохранение/сброс и результат изменения | C03 либо C05/B04; не базовое поле |
| Область поиска вокруг вложенного поля, её padding/высота, ширина и scroll списка | Селект B04/C05; это внешняя композиция относительно B02 |
| Выдача, типы, счётчики, popup/его привязка и выбор результата | Поиск C03 либо родительское меню; не B02 |
| Файлы/семейство шрифта | [Общий ресурс CoFo Sans](<../../../Ресурсы/Шрифты/README.md>) через токен; подключение в приложении проверяется отдельно |

Поле содержит корпус, ведущую лупу при её наличии, редактируемую строку и необязательное место для trailing action. Потребитель передаёт строку и принимает намерение изменить её; placeholder не становится значением. Доступное имя задаётся независимо от placeholder. Многословный запрос не расширяет корпус: применяются доступная ширина и документированная геометрия; точное поведение длинного введённого текста нативного поля не выводится из Figma TRUNCATE.

## Варианты и статус фактов

| Вариант | Подтверждение | Граница |
|---|---|---|
| global-search32 | Срез Figma поля494:3520 и текущий C03: белый корпус, рамка Gray/200, собственные внутренние отступы и типографика | Не использовать рамку выдачи вместо рамки поля. Фактическая ширина и позиция в хедере принадлежат C02/C03 |
| list-search32 | Высота/шрифт/placeholder перенесены из принятого B04. Дополнительные корпус/отступы/цвет строки — **наблюдаемый срез текущего FilterValueList CSS**, источник отмечен в YAML | Это не доказательство новых утверждённых Figma-значений или полного набора состояний. Фильтрация вариантов и DRAFT остаются у родителя |

Base применяется только к этим двум совместимым однострочным поискам. Пустой параметр не означает ноль или общий стиль DS. Наблюдаемые `focus-implementation` в YAML отдельно сохраняют существующий технический outline каждого применения; они не объявляют соответствие Figma State=Focused/active, не вводят новый продуктовый режим и не считаются новой визуальной приёмкой пользователя.

Поле селекта с выбранным значением и шевроном — trigger B04, а не редактируемый input B02. Его размеры/радиус, поворот стрелки и single/multiple не переносятся сюда. Checkbox, radio, time/number/range также не становятся текстовым полем по наличию HTML input.

## Применение и действия

| Контекст | Конфигурация | Следствие изменения и очистки |
|---|---|---|
| Глобальный поиск в хедере / Навигатор | global-search32; query/placeholder/доступное имя и trailing Clear от C03; ширина заполняет место хедера | C03 ведёт поиск и dropdown. Его Clear очищает query и закрывает dropdown; выбранные типы сохраняются. Escape/внешнее закрытие без выбора сохраняют query |
| Поиск значений в раскрытом селекте общей фильтрации | list-search32; query списка и наличие поиска задаёт B04/C05 | Изменяется поиск доступных значений текущего поля; выбор продолжает менять общий DRAFT. Нет собственного Apply или глобальной выдачи |
| Поиск в меню колонки | Тот же list-search32 через B04 embedded-list; ширина от внешней поверхности | FL-02 ведёт локальные значения/DRAFT/Apply. Ввод не применяет фильтр к таблице сам по себе и не закрывает глобальный поиск |

Два смысла поиска сохраняются при одной реализации визуального поля. Родитель задаёт обработчик и состояние: изменение строки не требует API-запроса и не доказывает наличие backend. У B02 нет собственного правила debounce, минимальной длины, алгоритма ранжирования, обязательности или отправки по Enter. Клавиши выбора результата остаются у C03, клавиши/транзакции списка — у B04/C05.

Вложенный поиск не наследует Clear глобального поиска. Отсутствие trailing Clear в его источнике не даёт права добавить кнопку или сбросить выбранные значения при очистке локального query. Показ/скрытие поиска задаётся конкретным списком; компактный источник без поиска не получает его автоматически из B02.

Внутренние inset считаются от внешней границы поля; stroke не увеличивает наружный габарит. Leading и trailing glyph не заменяют области ввода/действия и не получают оформление outlined-кнопки B01 по сходству формы. Если отсутствует подтвердившийся вариант, не подставлять global-search32 ради получения готовой палитры.

## Проверка и обновление

Документальная приёмка проверяет перенос значений и их статус, типы/ссылки YAML, отсутствие второй числовой копии поиска у B04, сохранность его внешней области поиска, два разных контекста query и маршруты к ресурсам. Схема/ссылки не доказывают готовность backend, совпадение с живой Figma или визуальную приёмку наблюдаемых CSS-стилей.

После реализации отдельно проверяются выбранный вариант, реальный шрифт, рамка/размеры/состояние, ввод, переданные действия и отсутствие изменения другого query/выбора. Новое внутреннее оформление ведётся здесь/YAML с проверкой C03/B04/C05. Данные, правила поиска/очистки/валидации и внешний результат меняются у фактического потребителя.
