# Пагинация списков

П4-14 · B17. Общий контракт панели страниц и её действий. [Параметры.yaml](<Параметры.yaml>) ведёт overlay64 и flow64, [формат](<../../../Ресурсы/Параметры компонентов/README.md>) — схему. Размер страницы списков сущностей и условие видимости задаёт [решение о пагинации](<../../../../context/target/Требования и границы.md#пагинация-списков--решение-1-ноября-2026>). Данные, индекс и внешнее размещение ведёт контракт списка.

## Условие видимости и данные

При известном общем результате N и действующем лимите pageSize панель видна только при N>pageSize. При N=pageSize она скрыта; при N=pageSize+1 показана уже на первой странице. При пустом результате панель отсутствует и сохраняется пустое состояние родителя. Видимость не зависит от высоты viewport, числа видимых строк, прокрутки или выбранного карточного/табличного вида.

Для списков сущностей поставки размер страницы равен 15. Компонент получает его от списка вместе с известным общим числом результатов. Счётчик группы, сегмента или полученный фрагмент списка не заменяют общее число результатов.

| Вход / намерение | Значение и граница |
|---|---|
| total | Известное общее число результатов после применённых ограничений, не длина видимой страницы |
| pageSize | Действующий положительный целочисленный лимит контекста; выбора размера страницы внутри текущего компонента нет |
| pageIndex | Текущий допустимый индекс от0. В подписи кнопки пользователь видит index+1; нормализация некорректного URL/индекса относится к родителю |
| label | Доступное имя панели по сущности списка; подпись «Страницы отчётов» не назначается источникам или участникам автоматически |
| onPageChange(index) | Намерение выбрать страницу с индексом от0. Получение записей, сохранение URL/history и контекста, обновление данных/текущего индекса — родитель |

В текущем [ListPagination](<../../../../references/implementation-current/components/ListPagination/ListPagination.tsx>) pages=ceil(total/pageSize), при pages<=1 возвращается null. Это реализация известного численного случая, не подтверждённый механизм неизвестного total. Применение получает согласованные total/pageSize/pageIndex; универсальную обработку произвольного невалидного ввода B17 не обещает.

## Устройство, состояния и механика

Слева находятся предыдущая страница, номера страниц и следующая; справа — фактический диапазон и подпись действующего размера страницы. Общие размеры, цвета, радиусы, тень, glyph и состояния кнопок читаются из YAML. Page buttons не заменяются круглыми action-кнопками B01. Выбор текущей страницы оформлен aria-current=page и отдельной подложкой, а не disabled.

| Событие / состояние | Подтверждённый результат |
|---|---|
| Выбор номера n | Передаётся onPageChange(n−1); текущий код передаёт намерение и при повторном выборе текущего номера |
| Предыдущая при pageIndex>0 | Передаётся pageIndex−1; на первой странице native disabled не допускает перехода назад |
| Следующая до последней | Передаётся pageIndex+1; на последней native disabled не допускает перехода вперёд |
| Изменение pageIndex/total/pageSize родителем | Обновляются текущая кнопка, границы disabled и диапазон; собственное состояние страниц в ListPagination не хранится |
| Первая/средняя/последняя страница | Начало диапазона=pageIndex×pageSize+1; конец=min((pageIndex+1)×pageSize,total). Последняя неполная страница не выдаётся за полный лимит |
| Фокус/клавиатура | Native button сохраняет Tab и стандартную активацию; наблюдаемый focus-visible ведёт YAML. Стрелки клавиатуры/Home/End, hotkey, автоскролл и сохранение фокуса не добавляются по аналогии с вкладками |

Навигация имеет aria-label контекста; стрелки — собственные доступные имена «Предыдущая страница»/«Следующая страница», img декоративны. Нет отдельного поля ввода номера, dropdown лимита, first/last-кнопок или перехода по одному статическому диапазону. Выбор вида/сортировка/фильтры не являются состоянием B17: правила сброса/сохранения страницы остаются у списков.

**Длинный ряд:** эталон Figma показывает1,2,3,4,…,999. Он не устанавливает полный алгоритм сокращения промежуточных номеров. Текущий ListPagination рисует все номера Array.from(length:pages), без многоточия; это ограничение текущей реализации для больших наборов, не точное воспроизведение999-страничного эталона и не утверждённый новый алгоритм. Для текущих небольших demo-наборов подтверждён численный механизм. Генерация большого ряда требует согласованного правила сокращения; B17 не выдумывает его и не подставляет статические999/9990 в фактический список.

## Варианты и размещение

| Вариант | Внутреннее отличие | Что сохраняет родитель |
|---|---|---|
| overlay64 | Абсолютная панель по нижнему краю своей области, вне вертикального scroll результатов | Сам позиционирующий контейнер, его размер, слой относительно соседей и доступный нижний резерв |
| flow64 | Тот же корпус, наблюдаемое position:relative/width100% в каталоге Источников | Внешний flow-wrapper и освобождение его места при скрытии |

Когда панель скрыта, место только под неё освобождается, собственный нижний отступ списка сохраняется. Нельзя механически назначать один padding всем применениям. Подтверждённые overlay-применения таблицы/подписок/вклада/избранных и связанных метрик используют резерв80 при видимой панели и16 при скрытой; это конфигурация их родителей, не внутренний padding B17. Источники выделяют flow-wrapper только при нескольких страницах. Панель не должна перекрывать последнюю доступную запись; absolute и численный z-index сами по себе не доказывают правильный конечный слой.

В YAML сохранён точный Figma shadow-color sRGB(0.06,0.11,0.23,0.12). Отдельный профиль observed-css показывает фактический CSS rgb(15,28,59)/12%; эти численные представления не молча округлены друг в друга. Он описывает источник, не отдельное пользовательское состояние. Выбранность, disabled и focus относятся к соответствующим отдельным кнопкам и могут наблюдаться в одной панели; это не исключающие состояния всей страницы.

В карточном и табличном видах каталога отчётов список резервирует 80 px при видимой панели и 16 px при скрытой. Это настройка каталога. [Композиция и проверенные страницы](<../../../Разделы/Отчёты/Контракт.md#сборка-каталога>).

## Документальная приёмка

1. При N=0, pageSize−1 и pageSize панель отсутствует; при pageSize+1 появляется на первой. На последней неполной странице фактический диапазон сохраняется.
2. Проверяются исходные параметры, отдельные кнопочные состояния, согласованные входы и контексты сброса/сохранения; неизвестный total и большие ряды не выдаются за решённые правила.
3. Из потребителя находятся нужный вариант, YAML, источник данных/резерва и совпадающий эталон. Проверяются Figma URL, самостоятельные SVG и локальные ссылки/якоря.
4. Проверка оформления/семантики документа не является новым браузерным прогоном или приёмкой всей реализации. П7 отдельно проверяет фактическую автономную копию, приложение/DS/Project Context этой порцией не меняются.
