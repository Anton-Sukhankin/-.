# Заголовок колонки · B22

## Граница и статус

Компонент владеет внутренним отображением подтверждённых семейств заголовков: подписью, внутренними интервалами, подсветкой и отдельными признаками открытого меню, применённого фильтра и применённой сортировки. Единственный численный владелец — [Параметры.yaml](<Параметры.yaml>). Значения вариантов не переносятся между семьями по сходству.

Целевые правила отчётного заголовка перенесены из принятого контракта таблицы; параметры generic-заголовков перенесены из «Видов Главной». `related-metric24` сохраняет прямое уточнение пользователя4ноября2026 о компактных заголовках; `usage-static48` — прямое решение о неинтерактивной истории. Дополнительные правила CSS ниже имеют статус наблюдаемого среза4ноября2026, а не новой визуальной приёмки. Живая Figma и приложение этой декомпозицией не проверялись.

Родитель должен задавать подпись и идентичность колонки, вариант, её место и ширину. Состав, порядок, общая сетка, закрепление и прокрутка колонок, фон/бордер всей шапки и расстояние до строк принадлежат таблице. Данные, сравнение и порядок записей, DRAFT/APPLIED, Apply/Reset/Clear, меню и его привязка остаются у родителей и [FL-01/FL-02](<../../../../context/target/Пользовательские пути/Фильтрация отчётов.md>). Компонент не должен присваивать статическому заголовку меню или сортировку по названию колонки.

## Подтверждённые применения

Последующее прямое уточнение пользователя4ноября: у ячеек с фильтрацией вертикальный padding8px при сохранении внешней высоты; сокращается внутренняя область взаимодействия. Действующие значения — report48 и source-filter52 в YAML. У источников сохранена структурная высота52px с прежним интервалом до строк; зона взаимодействия36px. У отчётов сохранена высота48px, зона32px. Горизонтальные отступы, шрифты и привязка меню к колонке сохраняются. Это заменяет прежние padding4px/область40px; исходные PNG не редактируются. Статические заголовки не получают фильтры и не меняются этим поручением.

| Вариант | Внутренняя композиция | Входящий маршрут и граница |
|---|---|---|
| `report48` | Внешняя ячейка → внутренняя область подсветки → подпись → один контрол фильтра/сброса → отдельная стрелка применённой сортировки, если передана | [Таблица отчётов](<../../Таблица отчётов/Контракт.md#применение-заголовка-колонки-b22>) и [фильтрация](<../../Фильтрация отчётов/Контракт.md#применение-заголовка-колонки-b22>); каталог и избранное используют одну семью |
| `source-filter52` | Существующая source-ячейка → область подсветки → название/контрол фильтра → отдельный сброс | [Источники](<../../../Разделы/Источники/Контракт.md>); структурная высота и интервал до строк сохраняются, геометрия по уточнению4ноября |
| `home-static48` | Статическая текстовая ячейка generic-шапки; первый заголовок получает собственный левый отступ | [Подписки и вклад Главной](<../../../Разделы/Главная/Виды.md#применение-заголовка-колонки-b22>); исходные generic-мастера не подтверждают меню |
| `related-metric24` | Статический `th`; первый заголовок получает собственный левый отступ | [Связанные метрики отчёта](<../../../Разделы/Отчёты/Паспорт/Контракт.md#применение-заголовка-колонки-b22>); действия последней колонки имеют скрытую визуально подпись у родителя |
| `usage-static48` | Статический текстовый `columnheader`; однострочная подпись, первый заголовок с собственным левым отступом | [История по месяцам](<../../../Разделы/Отчёты/Паспорт/Контракт.md#применение-заголовка-колонки-b22>); наследование оболочки ReportTable не даёт controls |

В `report48` индикатор должен идти после контейнера подписи с `content-gap`, а не прижиматься к правому краю колонки. В текущем ReportTable у первой подписи есть отдельный `current-first-content-padding-left`. Ширина примера isolated-ячейки не становится шириной любой колонки. Исходный геометрический пример: внешняя ячейка144×48 содержит область136×40; `content-justify` сохраняет MIN источника. Целевая подпись — одна строка с ENDING; текущий CSS отдельно задаёт ellipsis при переданной сортировке, что не считается проверкой всех длинных подписей.

Hover/Active используют буквальную заливку без binding; белые/голубые альтернативы не подставляются. Активный glyph сохраняет исходную привязку `VariableID:38d7e403d4659b516b3e7bf92e05d41fac0eae64/12577:4469`. Наблюдаемый CSS-token `--table-heading-hover` разрешается в ту же заливку и не изменяет статус исходного literal.

Параметры общего шрифта используют token `ui-font` и [канонический ресурс шрифтов](<../../../Ресурсы/Шрифты/README.md>). Figma-переменная muted530:272 отличается от muted113:18 доменной группы; одинаковое имя `muted` не разрешает заменить источник. `report48` использует типографику composed-шапки, а не независимые overrides технических PNG.

## Признаки и намерения report48

Обычный вид, открытость меню, применённый фильтр и применённое направление сортировки — отдельные входы. Родитель должен передавать открытость только для своей активной колонки, применённость фильтра — по APPLIED атрибута, направление — по применённой сортировке этой колонки. Временный выбор в DRAFT не должен менять эти применённые признаки.

| Условие / событие | Отображение или намерение компонента | Владелец результата |
|---|---|---|
| Меню закрыто, фильтр не применён, направления нет | Обычная подпись и нейтральный glyph фильтра; без стрелки | Родитель передаёт состояние |
| Наведение на обычный заголовок | Внутренняя подсветка `hover`; при уходе возвращается вид по оставшимся признакам | B22; наведение строки не заменяет это событие |
| Активация подписи доступной отчётной колонки | Намерение открыть меню именно этой колонки; якорь текущего заголовка | Родитель открывает локальное меню по FL-02 и возвращает открытость; B22 не применяет условие |
| Родитель сообщил открытое меню | Подсветка `open`; при отсутствии applied-фильтра glyph становится активным синим | B22; открытость не доказывает применение |
| Родитель сообщил applied-фильтр | Вместо исходного glyph показывается один круглый индикатор сброса с минусом | B22; исходный glyph не должен просвечивать под ним |
| Наведение на индикатор сброса | Серый вид `applied-hover`; текущий CSS также исключает обычный hover-фон заголовка только при наведении на сброс | B22; при одновременно открытом меню сохраняется подсветка `open` |
| Активация индикатора сброса | Отдельное намерение снять условие именно этого атрибута | Родитель/FL-01/FL-02; действие не должно одновременно открывать меню |
| Родитель сообщил применённое направление | Отдельная синяя стрелка после контрола фильтра; `asc` — исходная стрелка вниз, `desc` — её поворот `sort-desc-rotation` | B22; сортировка записей принадлежит родителю |
| Направление изменено или снято только в DRAFT | Прежняя применённая стрелка сохраняется | Родитель сохраняет APPLIED; после Apply передаёт новое направление либо его отсутствие |
| Applied-фильтр и сортировка одновременно | Индикатор сброса и отдельная стрелка видны вместе | Сортировка не добавляет атрибут к счётчику фильтров |
| Родитель закрыл меню | Подсветка открытости снимается; applied-фильтр и стрелка остаются по переданным значениям | Отмена/сохранение DRAFT принадлежит FL-02 |

Таким образом, при одновременных open и applied остаются подсветка открытого заголовка и один индикатор сброса; отдельная стрелка добавляется только при применённом направлении. Цвет активного glyph сам по себе не является applied-индикатором.

В наблюдаемом ReportTable подпись открывает меню через кнопку с именем «Фильтр «…»», `aria-haspopup="dialog"` и `aria-expanded`; отдельная кнопка сброса имеет имя «Сбросить фильтр «…»». Glyph и стрелка декоративны. `aria-sort` ячейки отражает ascending/descending/none из применённого направления. Наблюдаемая рамка focus-visible принадлежит внутренней области; эти CSS-параметры помечены `current-*` в YAML. Полный клавиатурный контракт меню остаётся у фильтрации; новые click-cycle направления, disabled/loading, таймеры и способы закрытия здесь не вводятся.

У статических вариантов нет подтверждённых входов open/applied/sort, интерактивного триггера или действия сброса. Подписка, вклад, связанные метрики и Usage должны сохранять свои статические заголовки. Наличие слова MAU, «Домен» или «Отчёт» не подключает к ним отчётный фильтр.

## Признаки и намерения source-filter52

Этот раздел расширяет действующее применение [каталога Источников](<../../../Разделы/Источники/Контракт.md#черновик-применение-и-индикация>). Прежняя декомпозиция сохраняла идентичность/геометрию source-filter52; она не принимала автоматически все source-переходы. У источников интерактивны только «Источник», «Описание», «Домен», «В аналитике». Подписи, наборы атрибутов и их меню остаются у каталога. У остальных колонок родитель выводит статический текст без фильтра, hover-контрола и сортировки.

Открытость и applied независимы. Родитель сообщает open только для текущей колонки, applied — если хотя бы один её атрибут имеет применённое условие. Изменение DRAFT не меняет applied-знак. source-filter52 не получает report48-сортировку и правило замены исходного glyph одним кругом: в зафиксированном source-binding активный glyph остаётся в кнопке подписи, а отдельный круг сброса стоит рядом. Это наблюдаемый binding согласованного source-контроллера, не новый универсальный DS-паттерн.

| Условие / событие | Отображение / намерение B22 | Результат у родителя |
|---|---|---|
| Нет open/applied | Нейтральный glyph, отдельный сброс скрыт | Текущая выдача без нового действия |
| Наведение | Внутренняя подсветка по source hover | Условия и выдача сохраняются |
| Нажатие подписи / нативная активация кнопки | Передать идентичность колонки и её якорь | Открыть её меню с копией applied в DRAFT |
| Open без applied | Подсветка и active glyph; отдельного сброса нет | Черновик остаётся у меню |
| Applied при закрытом меню | Active glyph и отдельный круг сброса | Выдача и условия уже применены |
| Open+applied либо hover+applied | Подсветка, active glyph и отдельный сброс видны вместе | Открытость не снимает применённые условия |
| Нажатие отдельного сброса | Намерение снять условия только этой колонки; не открывать её меню | Каталог немедленно очищает её applied-атрибуты |
| Отмена/закрытие меню | Снять только open; applied-индикация по прежним значениям | Родитель отменяет DRAFT |

Геометрия, активная/нейтральная подача и named combinations находятся у source-filter52 в YAML. Полная ширина/фон th, sticky-позиции и интервал до строк остаются у таблицы. Footer Reset меню и его возврат фокуса — отдельный путь у каталога, а не внутреннее действие B22. Колонка «Источник» относится к platform+layer: их состав не дублируется в базовом компоненте как новый справочник.

В SourceTable кнопка подписи имеет имя «Фильтр: …», aria-haspopup=dialog и aria-expanded по open; отдельная кнопка — «Сбросить фильтр: …». Изображения декоративны. Фильтр и минус используют целые текущие filter.svg/filter-active.svg/filter-minus.svg, перечисленные ниже; размер минуса отличается от размера круга. Нажатие сброса не вызывает обработчик открытия. Сортировка, aria-sort и click-cycle направления этим применением не вводятся.

Адресный code/CSS-срез — SourceCatalog.tsx и Sources.module.css версии [prototype-2026-11-04-c1](<../../../Ресурсы/Срез прототипа/README.md>). [Текущий каталог,1440×900](<../../../Ресурсы/Срез прототипа/frames/sources.png>) показывает ordinary source52; [манифест](<../../../Ресурсы/Срез прототипа/manifest.json>) фиксирует SHA256 и состояние. Для open+applied доступен [кадр источника с двумя группами меню](<../../../Ресурсы/Срез прототипа/frames/source52-open-applied.png>); [после footer Reset](<../../../Ресурсы/Срез прототипа/frames/source52-cleared.png>) остаётся отдельный domain-фильтр. Exact URL, действия и состояния6/count3 →7/count1 принадлежат родителю и манифесту. Остальные комбинации не объявляются снятыми только из-за наличия этих кадров; механику действий проверяют отдельно. ## Приёмка и неизвестное

Проверить route каждого родителя к варианту/YAML; не изменять состав колонок при подключении. Для report48 раздельно проверить обычное состояние, hover, open без applied, applied без open, open+applied, стрелку без applied-фильтра и стрелку вместе с ним. Изменение DRAFT не меняет applied-признаков; Apply обновляет их через родителя; сброс передаёт отдельное намерение. Статические варианты должны оставаться без controls. Числа, типы, источники и ресурсы проверяются по YAML и сохранённым манифестам; отсутствие изображения не заполняется выдуманной геометрией.

Точная библиотечная привязка и универсальное соответствие DS не установлены; технические Figma IDs не задают React API. B22 не вводит серверные расчёты, права, persistence, menu transaction, новые колонки или мобильные состояния. Приёмка этой порции документальная; визуальная/интерактивная проверка реализации и переносимый пакет А8 остаются последующими задачами.
