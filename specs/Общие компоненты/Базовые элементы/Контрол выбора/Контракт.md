# Чекбокс и одиночный выбор

Владелец B06: графический checkbox и нативная семантика одиночного выбора в подтверждённых применениях. [Параметры.yaml](<Параметры.yaml>) ведёт точные значения и происхождение. П4-04 переносит факты из B04/C05 и адресных источников форм, не изменяет интерфейс или действия. [Формат и проверка параметров](<../../../Ресурсы/Параметры компонентов/README.md>) общие с другими базовыми элементами.

## Граница и маршрут

Читать конфигурацию потребителя → нужный вариант этого контракта/YAML → конкретный SVG или изображение. Обратная ссылка на родителя объясняет внешний контекст; она не требует загружать все списки и формы.

| Факт | Владелец |
|---|---|
| Графический квадрат, native control, их размеры/совмещение и подтверждённые различия вариантов | Этот контракт и YAML |
| ID/подпись/checked, состав группы, связь с атрибутом и результат изменения | Потребитель |
| Строка списка: высота, ширина, текст, интервал до квадрата, hover/selected-подложка и текст статуса | B05 в [контракте селекта](<../Строка списка/Контракт.md#строка-выбора>) |
| Доступные значения, смысл «Все», DRAFT/APPLIED, поиск и Apply/Reset | B04/C05 и FL-01/FL-02 |
| Четыре флага профиля, их атрибуты, расписание, сохранение/отправка | [Паспорт отчёта](<../../../Разделы/Отчёты/Паспорт/Контракт.md#контролы-выбора-в-рассылке>) / RD06 |

Входы по смыслу: вариант, устойчивая идентичность/значение, checked, подпись или доступное имя и намерение изменения; для radio — принадлежность к одной независимой группе. Это роли данных, не обязательные имена API/props. Состояние хранит родитель. Caption не заменяет идентичность: одинаковая подпись «Последнее значение» относится к разным атрибутам формы.

## Варианты и статус источников

| Вариант YAML | Устройство | Статус и ограничение |
|---|---|---|
| filter-checkbox16 | Видимый квадрат и прозрачный native checkbox в обёртке; подпись принадлежит B05 | Размер квадрата/обёртки сохранён из П3. Дополнительные рамка/радиус/совмещение/focus — наблюдение FilterValueList CSS; checked-графика — точный существующий SVG |
| form-checkbox16 | Native checkbox с пользовательским оформлением и подписью «Последнее значение» | Подтверждённый флаг формы; его численные стили — наблюдение MailingsTab CSS, не новая приёмка Figma. Внешний отступ до флага задаёт форма |
| text-radio | Прозрачный native radio занимает родительскую строку; собственный кружок radio скрыт | По уточнению4ноября выбранная строка показывает одну DS-галочку без квадрата; вид индикатора принадлежит B05, native radio и единственность выбора сохраняются |

У radio нет наследуемого квадрата16px или самостоятельной фиксированной высоты. Его область заполняет фактическую строку. Визуально скрытый native control остаётся доступным для фокуса/выбора; его нельзя заменить на hidden/display:none/aria-hidden. У filter-checkbox декоративный mark исключён из дерева доступности, а native input сохраняет семантику. Радиус и цвета непоказанных hover/disabled/indeterminate не добавляются по аналогии с DS.

## Действия и состояние

1. В checkbox-применении изменение одного checked передаёт родителю намерение переключить соответствующий ID. Остальные ID не снимаются только из-за выбора нового. Повторное переключение может снять этот флаг; семантика «Все», ограничения набора и следствие для данных принадлежат потребителю.
2. В radio-применении выбор нового значения заменяет прежнее в той же группе. Повторная активация выбранного значения не очищает группу. Нельзя хранить несколько эффективных checked в одной radio-группе или объединять независимые экземпляры списка одним общим именем.
3. Для подтверждённого статуса native radio поддерживает Arrow keys и Space; focus-visible должен оставаться различимым. Это правило не назначает новый клавиатурный режим всем полям/формам. Наблюдаемые outline в YAML — технический срез существующей реализации, не добавленные Figma-состояния.
4. Выбор значения не выполняет Apply. Общая панель меняет общий DRAFT до FL-01, меню колонки — локальный DRAFT до FL-02. Исходы закрытия/Reset сохраняют владельцев.
5. Флаг «Последнее значение» меняет локальное состояние соответствующего атрибута формы. B06 не вычисляет актуальное значение, не применяет профиль, не сохраняет настройку на сервере и не выполняет рассылку. Показанная подпись о подстановке не доказывает готовый производственный механизм.

Для label/группы сохраняется доступное имя и связь с конкретным значением. Одинаковые caption в форме не превращают четыре флага в один общий boolean. Продуктовые disabled/ошибки/загрузка и все возможные ограничения выбора не восстанавливаются из библиотечных состояний; недоступность передаёт фактический владелец, если она определена.

## Геометрия и ресурс checked

Два размера квадрата и файла различаются. Существующий [SVG галочки](<../../../../assets/images/column-filter/checkbox-checked.svg>) имеет intrinsic/viewBox16×20; plate занимает16×16 с верхним inset2. В filter-checkbox16 файл используется с исходной высотой в обёртке. Не обрезать viewBox до квадрата и не считать высоту файла высотой всей строки.

В form-checkbox16 существующий CSS использует тот же SVG как background размером16×16. Это наблюдаемая масштабированная подача, не доказательство идентичной checked-геометрии двух вариантов и не согласованное исправление пропорций. YAML сохраняет размеры ресурса и его подачи отдельно. Точный цвет plate файла #007BFB не нормализуется к #007BFC оформления формы; байты SVG не меняются.

Цвет/размер и focus, прочитанные из CSS, помечены observed-snapshot в источниках. Они не выдаются за вновь измеренные Figma-свойства. Для новой визуальной приёмки варианта сравнивать соответствующее состояние и реальный ресурс; статический unchecked-кадр формы не подтверждает checked/focus.

## Применения

| Потребитель | Вариант / данные | Граница результата |
|---|---|---|
| Дискретные значения панели и меню колонки | filter-checkbox16; ID, label и checked текущего значения от B04/C05 | Множественный выбор; разные общая/локальная транзакции не объединяются |
| Статус общей панели | text-radio; одна группа, текущее значение от C05 | «Все», «Проверено», «Не проверено» и счётчик атрибутов принадлежат C05. «Все» не универсальная команда radio |
| Профиль рассылки | form-checkbox16; четыре самостоятельных field ID и checked от формы | Caption одна, поля разные; нет подтверждения серверного вычисления/применения/отправки |

**Контрольные разборы.** Выбор второго домена оставляет первый выбранным; общий Apply остаётся FL-01. Выбор другого статуса снимает прежний статус, повторный выбор оставляет один; видимого radio нет. В рассылке изменение «Последнего значения» РГП (ПРОЕКТ) не переключает одноимённый флаг другого атрибута. Это извлечение требований из документации, не новый прогон приложения.

Кнопки дней недели и способов получения, переключатель вида, чипсы и скрытые defaults Tree не являются вариантами B06 по наличию selected. Toggle из исходного DS-семейства продукту этим контрактом не назначается. Каталог метрик с немедленными селекторами не получает text-radio только по слову «одиночный».

## Приёмка и изменения

Документальная приёмка: типы/YAML и источники, перенос двух размерных параметров B04 через ссылки к B06, сохранность прочих параметров строки, независимые multiple/single/флаги, ограничения источников и маршруты чтения. Она не подтверждает runtime, интеграцию, непоказанные визуальные состояния или производственную рассылку.

При реализации отдельно проверяются нужный вариант/состояние, native checked и видимый mark, корректная группа radio/доступность, сохранение других ID и соответствующий Apply. Общие внутренние параметры меняются здесь/YAML с проверкой потребителей. Смысл значений, внешняя композиция, данные и результат действий меняются у родителей.
