# Каталог данных · пакет для frontend-разработчика

Проверенный срез: **2 ноября 2026**, после добавления «Задач» в боковое меню. Это отдельная передача контекста для реализации интерфейса по документации; исходный проект, записи встреч, исследовательские архивы и рабочие журналы сюда не входят.

## Начало работы

1. Прочитать [обзор спецификаций](specs/Обзор.md), затем контракт порученного раздела: [Главная](specs/Разделы/Главная/Контракт.md), [Навигатор](specs/Разделы/Навигатор/Контракт.md) или [каталог Отчётов](specs/Разделы/Отчёты/Контракт.md).
2. Обследовать относящийся код, существующие компоненты, библиотеку, шрифты и команды проверки в репозитории реализации. Составить план соответствия текущего кода принятым контрактам. Этот репозиторий не содержит приложение и не назначает новый технологический стек.
3. Для каждой порции подключать контракт конкретного компонента, обязательные зависимости и совпадающие изображения состояний. Порядок реализации и критерии перехода находятся в [регламенте](specs/Обзор.md#регламент-последовательной-реализации).
4. Реализовать порцию, сверить геометрию, типографику, состояния и описанное поведение. Общий компонент реализуется один раз с проверкой его потребителей. Продолжать в рамках порученной области.

## Состав и границы

- `specs/` — три раздела, восемь общих контрактов, галереи, PNG/SVG, манифесты и файлы шрифтов.
- `context/` — только связанные владельцы требований, семантики данных и путей, необходимые спецификациям. Эти документы не расширяют порученный объём. Читать нужный раздел, а не весь контекст сразу.
- [Шрифты](specs/Ресурсы/Шрифты/README.md), [зависимость дизайн-системы](context/design-system.md), [контрольные суммы и происхождение](PACKAGE.json).

Полный паспорт отчёта, самостоятельные Источники/Метрики/AI Hub/Бизнес-словарь/справочники/FAQ и внутренняя страница «Задачи» не получили полных визуальных контрактов в этой передаче. Пункт меню или назначение перехода не означает поручение реализовать соответствующий раздел. Сведения этих типов в поисковой выдаче описаны в границе самого поиска.

## Как трактовать источники

Конкретное состояние, параметры и принятую визуальную композицию читать у владельца в `specs/`; продуктовые условия — по его ссылке на `context/`. Ранние основы, предложения, примеры и неизвестные сохраняют явно указанный статус. При существенном противоречии зафиксировать конкретные пункты и приостановить только зависящий результат, не придумывать новое правило.

Ссылки на Figma сохранены; они требуют доступа к соответствующему файлу. Архивные доказательства и текущие старые интерфейсы не перенесены: их ссылки в экспортной копии представлены текстовыми названиями. Не искать исключённые рабочие папки для обычной реализации. Исходные документы проекта не изменены упаковкой.

PNG сверяют с теми же размерами, состояниями и демонстрационными данными. Счётчики и имена не становятся константами продукта. Скриншот не задаёт API, права или алгоритм. Файлы шрифтов переданы без установки. Подготовка пакета не доказывает готовность backend, приложения или работающего прототипа. Пробная реализация пока не запускалась.
